# 工作台界面

## 1. 目标与归属

按“工作台完善 → 编辑器完善 → 业务交互接入”推进前端开发，使用户能够找到文档、可靠编辑，
再在同一工作区完成真实业务处理。三个步骤是开发顺序，均服务于 Demo 与随后一个月完善，
不增加第三个交付阶段，也不延后[产品规格第 13 节](01-product.md#13-十二天-demo-与一个月完善里程碑)的业务闸门。

本规格负责页面结构、操作入口、状态呈现、响应式、键盘交互及 UI 验证。
业务输入、权限、事实、金额、来源、任务、复核与成果导出由[产品规格](01-product.md)负责；
Word 引擎和文件往返由[Word 编辑规格](03-word-editing.md)负责；
文档存储和当前会话隔离由[数据库规格](04-database-deployment.md)负责。

合同审查按问题展示风险、影响和建议，原文、依据、关联修订及待确认内容随对应问题展开；缺失原文须明确说明，不把未核实项当成已解决。修订不完整时保留已完成的审查结果和具体状态。修订建议稿的原文、改文及需确认的关键值可逐项对照；人工确认及导出限制见产品规格 §4.2.1。
本规格中的界面数据是上述契约的展示，不另立业务规则或授权方式。

2026-10-22 的实现基线已有文档/规范库页签、DOCX 编辑、服务端保存与导出。
以下新增交互及验收是开发目标，不表示已实现或通过；实现证据另存 `docs/reviews/`。
三个步骤规定实现和交付的优先顺序，不要求把全部界面回归串行完成后才允许合同纵向联调。
文档选择、保存、冲突保护及版本读取等必要基础可用后，业务联调可与响应式、视觉细节和其余 WD 验证并行；
业务能力对用户开放仍须满足 §5.1，未完成的 UI/WD 项不能因此记为通过。

| 顺序 | 本步交付 | 开始条件 | 完成条件 |
| --- | --- | --- | --- |
| 步骤一：工作台完善 | 文档列表、检索、操作层级、空/加载/失败状态 | 现有文档服务可用 | UI-01—UI-06、共用界面检查通过 |
| 步骤二：编辑器完善 | 面板布局、保存反馈、离开保护、异常恢复与键盘操作 | 文档列表和打开入口可用，现有 DOCX 闭环可用 | UI-07—UI-13、相关 WD 回归通过 |
| 步骤三：业务交互接入 | 项目上下文、任务、来源、结构化成果、修订和复核 | 文档选择、保存、冲突保护及版本读取基础可用，可开始纵向联调；对用户开放须满足 §5.1 | 按 §5.7 顺序交付，分别通过 UI-14—UI-23 和对应业务 AC |

## 2. 信息架构与官方来源

顶层保持“文档 / 规范库”两个页签。`/` 默认打开文档，点击文档进入“左侧编辑器 + 右侧 Agent”。
这一结构沿用 2026-10-22 确认的方向，替代历史布局 A；四业务能力不新增为顶层导航。

步骤一、二保持右侧 Agent 会话区域；步骤三在该区域内增加“会话 / 任务 / 成果”页签，
业务类型及操作放在任务和成果内。来源以临时详情面板查看，不增加常驻第三栏。
项目选择位于工作台和编辑器页头，属于步骤三，不替代顶层两个页签。
会话发送保持 §5.6 的边界，任务及成果入口可以独立使用。
项目文档页在业务能力可用时提供“开始业务”入口，进入同一任务工作区，无需先打开或新建文档。
未绑定文档时左侧显示所选材料预览；无所选材料时显示“未选择资料”及选择入口，右侧默认任务页签。
文书流程允许直接选择固定模板及录入拟约定输入，不为了取得任务入口而创建空白 DOCX。

## 3. 步骤一：工作台完善

### 3.1 文档列表与操作

输入是当前授权范围内服务端返回的文档元数据；输出是过滤后的列表，或用户选定文档的已保存版本。
步骤一、二沿用现有会话隔离；步骤三按当前项目读取，权限见 §5.1。

- 页头保留产品名称和“源代码”；文档区域的主操作为“新建文档”，次操作为“导入 Word”。
- 桌面表格包含文档名称、创建方式、更新时间。创建方式由 `authored / imported / copy`
  分别显示为“新建 / 导入 / 副本”，不据此推断材料真实性或业务来源。
- 标题是可聚焦的打开入口；同名文档按独立 ID 保留，不按标题合并。空标题沿用“未命名文档”。
- 更新时间取服务端 `updatedAt`，按 Asia/Shanghai 显示到分钟；默认降序，同一时刻按 ID 升序稳定排列。
  列表不因页面重绘改变已保存的时间，不显示虚构修改记录。
- 提供“搜索文档”输入，去除查询首尾空白后按标题做大小写不敏感的子串匹配，中文按原文匹配。
  清空查询恢复完整授权列表；步骤一不检索正文、不调用模型、不增加批量操作或文件夹。
- 窄屏优先保留完整操作入口与文档名称，将创建方式和时间放入名称下方；长标题可换行或截断，
  但必须有键盘可用的完整名称查看方式。返回列表保留本次检索条件；刷新无需保留该条件。

“新建文档”创建真正空白 DOCX；“导入 Word”校验后保存独立原件；点击标题打开明确的保存版本。
格式、大小、结构和原件保护仍按 Word 与数据库规格执行，不因 UI 接受文件而跳过服务端校验。
匿名资料新建和导入前显示数据库规格规定的实际到期日，供用户确认；期限配置错误时显示操作错误，
不假定无限保留。到期或迁移导出窗口结束后停止相应访问，并按数据库规格呈现允许的操作。
普通到期或迁移窗口结束后提供“开始新会话”，由用户明确确认旧资料不移入新会话；
成功后清空旧文档、查询和输入视图，进入独立空列表，可创建新资料，不延长或恢复旧资料权限。
首屏、焦点恢复及期限提醒先读取服务端会话，接受当前请求代次后设置上下文，再读取文档列表；
本地时钟只触发核对。上下文切换或失效撤下旧编辑器，有未保存更改时保留必要告知。
缓存版本下载及编辑内容序列化前重新请求服务端文档以核对访问；下载仍使用用户选定保存版本的
原有字节，不用核对请求返回的较新版本替换。迁移导出窗口只提供已保存版本的直接下载，不挂载编辑器。
本步不增加删除、历史版本浏览或规范管理入口。

### 3.2 加载、空状态与失败

| 状态 | 显示与可用操作 |
| --- | --- |
| 首次读取 | 显示加载状态，不先显示“暂无文档”；依赖列表或当前操作完成的按钮禁用 |
| 读取成功且无文档 | 显示“暂无文档”，提供新建和导入入口 |
| 有文档但查询无匹配 | 显示“未找到文档”，提供清空搜索操作，不误报资源不存在 |
| 首次读取失败 | 显示简洁错误与“重试”，不把失败当作空列表 |
| 刷新失败 | 保留此前已读取列表并显示刷新失败；再次打开仍由服务端鉴权 |
| 校验、导入或打开中 | 显示实际操作名称，禁止重复提交和冲突操作；允许取消本地校验或等待 |
| 文件或打开失败 | 显示可操作原因，保留列表与查询条件，允许修正输入或重试 |

取消不承诺撤销已提交到服务端的创建或导入。若服务端已保存，刷新后仍应能看到该文档；
迟到响应不能自动打开用户已取消的文档，也不能覆盖当前新打开的文档。

规范库保持“暂无规范”。本轮不支持上传、编辑、发布或凭示例填充规范；
后续可用知识及规则仍须满足产品规格的核对和发布要求。

## 4. 步骤二：编辑器完善

### 4.1 布局与上下文

输入是所选文档 ID、已保存版本及该文档的会话输入；输出是保存的新版本或该版本的 DOCX 下载。
标题、正文和会话输入按文档隔离，切换文档先处理未保存更改。

页头包含返回文档、可编辑标题、保存状态、保存和导出 Word。
保存或导出因 DOCX 未支持结构被拒绝时，显示明确错误，并提供“仅保留正文另存”确认；确认后打开新副本，原文档及其版本不变，格式丢失范围须在确认框说明。
地域提供省级候选并规范“北京市/北京”等后缀写法，同时说明地域用于确定适用规则和审查范围；审查选项与外发/资料确认分组展示，确认文案不展示 token、停止阈值等内部数值。
合同报告按风险等级标记（重大、一般、提示、待核实）并优先展示高风险类别；阶段性结果只在顶部提示一次，“复查未完成”不逐条重复。引用原文不展示内部 UUID，并提供在正文中定位/高亮当前引文的操作。
报告可展开到较宽阅读区域，并可导出 Word 报告（保留 Markdown 作为次要格式）。处理记录按“第 N 次 · 业务 · 时间”标识；款项核对提交前显示建议材料清单，结果明确“有条件测算”或“不能形成确定金额结论”以及已核对/待复核条目数量。
正文采用引擎官方画布与工具栏，不重做 Word Ribbon，不开放未验证的 Word 特性。
Agent 区域显示当前文档名称，长名称有完整查看方式，不显示其他文档的输入或结果。

桌面默认编辑器 70%、Agent 30%，沿用现有最小比例 35% 和 25%，允许拖动及键盘调整。
视口小于 768 CSS px 时按编辑器在上、Agent 在下纵向排列，默认比例相同；
标题和操作换行，内容区各自滚动，操作按钮和会话输入不能被挤出可访问区域。
响应式订阅沿用 `useSyncExternalStore`，改变方向不得重建引擎或清空输入。
本步不持久化面板比例，不引入跨设备布局同步。

纸张在编辑器画布内水平居中；纸张宽于面板时从左侧起可完整横向滚动，不裁切页首。
打开及重开文档默认适应宽度，保留真实纸张尺寸、页边距和分页，不要求用户先点击开关消除宽屏留白。
手动选择 100% 时继续居中显示。提供可用键盘操作的
“适应宽度”开关，开启后使用引擎实际面板宽度持续适配，缩放范围 10%—200%，总计预留
64 CSS px 的横向画布空间；达到边界时仍保留滚动。关闭开关保持当前比例，
在官方缩放菜单选择数值后退出适应宽度；再次开启恢复自动适配。
缩放及面板调整不重建引擎、不修改正文、不产生未保存状态，不持久化视图比例。
加载或引擎失败时禁用适应宽度，重新加载按默认视图恢复；保存期间沿用工作区操作锁定。
验收归入 UI-07、UI-13：验证默认及重开自动适配、手动 100% 居中、宽屏自动放大、调整面板后重新适配、
手动比例保持、窄屏横向滚动及键盘切换，并回归正文输入、保存重开和导出。

### 4.2 保存、导出与失败反馈

| 状态 | 操作约束 |
| --- | --- |
| 文档加载中 | 显示“正在打开文档”；引擎就绪前禁用保存、导出和依赖正文的业务操作 |
| 已保存且无修改 | 保存禁用；导出读取该版本原有字节，不重新序列化或生成正文 |
| 有未保存修改 | 显示“未保存”；标题、正文或会话输入变化均进入此状态 |
| 保存处理中 | 显示“正在保存”；锁定序列化涉及的输入，禁止重复保存、导出和切换 |
| 保存成功 | 仅在服务端事务成功后显示“已保存”，更新保存版本及列表元数据 |
| 保存失败 | 保留编辑内容并允许重试，不显示“已保存”，不自动离开 |
| 保存冲突 | 保留当前编辑和服务端新版本；阻止覆盖保存及依赖该保存的导出，提供“另存为新文档” |
| 正在导出 | 显示实际导出操作，禁止重复触发；与保存阶段的反馈分开 |
| 导出失败 | 保留已保存版本和当前编辑，允许重试同一版本，不返回原件冒充编辑结果 |

保存和 `Ctrl/Cmd+S` 使用同一操作。未修改时快捷键不创建冗余版本。
DOCX 导出有修改时先保存，下载本次保存的同一份字节；无修改时直接读取保存版本。
浏览器发起下载不等于文件已写入用户设备，不显示无法核实的“已下载”状态。
这些是普通 Word 文档操作，业务成果的校验、复核和导出另按 §5.5 与产品规格处理。

返回、切换文档或项目、登出前，有未保存修改时提供“保存并离开 / 放弃更改 / 取消”。
保存失败留在当前编辑器；冲突时保留另存能力，不能通过“保存并离开”覆盖新版本。
刷新和关闭窗口接入原生离开保护；只承诺成功保存版本可恢复，不以提示框代替持久化。
加载超时或引擎异常按 Word 规格显示原因；重试重新加载前同样处理可能尚存的未保存内容。
步骤三同一次导航的保护覆盖整个工作区，具体规则见 §5.2，不只检查左侧 Word 的修改。

### 4.3 Agent 输入边界

步骤一、二允许编辑和保存待发送内容，发送按钮禁用；不发模型请求，不产生模拟回复、虚假进度
或开发状态标签。空会话仅显示“暂无会话”，不加入说明段落。
输入属于用户陈述，不自动成为材料事实，也不能授权工具操作或覆盖文档。
步骤三仅在 §5.6 的条件满足后开放应用侧会话；引擎内置 AI、网络校对和遥测仍按 Word 规格关闭。

## 5. 步骤三：业务交互接入

### 匿名合同审查联调

新审查表单仅确认用户代表的专业分包人立场、地域与材料处理授权，不预填项目场景。
新任务默认多 Agent，真实阶段分别显示识别场景、主审合同与独立复核。复核期间保持主审结果可读，显示实际已复核/总规则数。
报告以「AI 复查」呈现机器复核；首页显示未完成状态及需人工核对数，详细进度、意见与原文定位按需展开，机器「保留」不表示人工通过。
正常完成的主审不得掩盖未完成的独立复核；复核疑点不自动删除或改写主审建议。
保存版本解析后显示真实「识别场景」阶段；匹配后报告显示场景名称，理由及可定位的原文证据放入详情。
场景不支持或待确认时显示相应状态、原因及待补信息，不显示空风险摘要或「未发现问题」，也不提供无效的继续原任务操作。
判断可随用户补充材料后的新任务重新进行；不改变历史任务对应版本及固定场景。场景停止卡片允许选择可用场景并填写理由，明确确认费用与外发后创建新任务；新任务显示“基于任务 xxx 手动重选”。仍须服务端适配检查，不提供更改场景的 retry。

现有匿名 DOCX 工作区保留独立合同审查联调入口，不计为本节的账号/项目业务开放或验收。
编辑器右侧使用官方 Tabs 组合「合同审查 / 备注」，保留步骤二的保存、离开、冲突与键盘保护。
F6 从正文切到备注并聚焦输入；切换右侧页签保留表单和任务状态。保存版本变化后必须重新确认外发授权。
文档列表在有效可编辑会话内展示本会话任务；新会话清除旧任务选择与视图，过期或只读时不提供新审查入口。
提交、轮询、原文定位、取消和继续原任务遵循架构的网页任务契约以及数据库会话/期限守卫。
已记录 token 达到原任务停止阈值时，显示停止原因并保留已有结果，不提供不能越过该阈值的「继续原任务」操作；新分析须重新确认输入和授权。
内置资料待核对时仅 debug 模式可提交，确认与报告持续展示未核对标记；published 模式保持拒绝。

报告首页依次展示「合同审查报告」、场景与立场、问题数及涉及类别数、「优先处理的问题」、
「需要进一步确认」、「尚未完成的检查」和导出操作。未完成或执行错误的结果明确标为初步结果，不能暗示整份审查通过。
问题按六类归组，以付款、结算、工期、变更、责任分担、争议解决的简明名称展示；每类默认显示最严重的一项问题及一句「修改方向」，
首页说明只展示各类优先项，并提供「查看本类其余 N 项问题」，不能把代表项当作整类完整结论。
组内按严重程度、原文段落排序；每项的规则编号、等级、原文、来源及核对状态、影响、完整问题、建议与 AI 复查意见放入详情，保留原文定位及待人工复核状态。
历史长文本的预览分别最多 80 / 120 字，省略处明确标记；全文和不可变结果保持原样，
不追加模型调用生成摘要。报告级依据待核对声明集中显示一次；旧 pending 中明确的共性调试声明不计为客户待确认事项，原文仍在详情保留。
仅对调试模式、整段匹配已知共性声明的内容作展示归类；混合实质疑点、未知文字和正式模式内容保守保留，不用关键词删除具体依据疑问。
实际事实/依据疑点按原文去重并保留关联规则，列入「需要进一步确认」；它们不等于客观事实已确认。
后端占位项、未定位项及没有有效结论的拒绝项按规则去重，单列为未完成检查，不混入需补材料数量；旧报告的已知占位说明兼容同样处理。
存在未覆盖类别、解析/已读范围不足、结果非成功、执行错误或 AI 复查未完成时，首页保留简明未完成提示；具体编号、覆盖和错误记录可展开。
AI 复查疑点数量保持可见，各条意见可按规则查看；详细警告及原始待核实记录保留在检查详情中，不把未知警告静默过滤。
Markdown 报告沿用相同分组与详情层级；JSON 继续完整保存结构化记录。

验收：多条同类问题只默认显示一个优先项，展开后条目数与原始 findings 一致；
长文本可还原全文和逐条来源；正常无风险与全部条目被拒绝的结果分开显示；
部分完成、待核实及未覆盖不能因折叠而消失；重复声明不扩大待确认数量，混合疑点及明确否定/冲突不能被声明归类吞掉。
无效占位不出现「第 0 段」，场景停止不出现风险结论，网页与 Markdown 数量一致且不修改 JSON。展开操作支持键盘与窄屏。
界面组合采用官方 [Collapsible](https://ui.shadcn.com/docs/components/radix/collapsible) 示例。

匿名联调表单增加明确的「生成合同修订稿」选择，提交和外发授权覆盖该操作。新修订流程的成果默认显示独立修订稿状态、修改处数、最多三条修改摘要及真实待确认事项。
通过结构及完整独立核对并保存 Word 工件后显示「导出修订建议稿（Word）」；未完成或有问题时说明原因，不伪造可下载文件。
原合同审查、逐段前后对照、完整修改后正文及 AI 核对意见放入可展开详情；不自动写入当前编辑器。历史报告保持原展示，修改后的合同不会冒用原合同的机器核对状态。


### 5.1 准入条件、项目与权限

#### A1 登录与退出交互

以其[表单源码](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/new-york-v4/blocks/login-01/components/login-form.tsx)
为起点，保留 Card、FieldGroup、Field、Input、Button 的结构、间距与标准变体。
必要偏离仅为受控账号契约：邮箱改“账号”（text，autocomplete=username），
密码使用 autocomplete=current-password；移除注册、找回密码、Google 登录和说明段落，
标题为“登录衡鉴”。不添加宣传栏、背景插画或自定义装饰。

状态为可输入、提交中、失败和成功；提交中禁止重复按钮/Enter 请求，保留可访问的忙碌状态。

限流提示对应服务端 Retry-After，不自动重试；成功后的回跳和目标重新授权遵循产品 §3.2。

主动退出先经过 §5.2 的工作区未保存对象保护；保存全部成功或明确放弃后才请求退出。
取消或保存失败留在原工作区；退出请求失败显示实际错误，不能宣称服务端已撤销。
退出成功清理受保护视图和请求，再回到登录页。失效/撤权则立即停止受保护操作并清除资源视图，
未保存输入仅作为待处理状态保留，不允许离线另存或下载绕权；重新登录后仍需重新授权，
不自动提交此前输入。跨页签无需新增通知基础设施，重新聚焦、导航和资源请求时复查会话；
其他页签的有效旧视图不得在新的请求失败后继续展示为可操作状态。

匿名工作台页头提供账号入口：未登录显示“登录”，已登录显示当前账号与“退出登录”；退出成功后回到登录页，退出失败显示实际错误。
该入口只呈现会话状态，不接管或清除匿名文档会话，也不作为项目权限依据；会话检查失败须显示为暂不可用并提供重试，
不得显示为已登录或未登录。

上述设计按 UI-14/UI-15 验证；工作区所有未保存对象接点由 A2 交付，
项目权限与撤权由 C1/C3 联验，未联通时不能单独宣称该项界面验收通过。

每项业务开放前，服务端须已实现并验证该项业务所需的登录与可撤销会话、项目成员授权、
不可变资料及来源、持久化任务、保存版本和输出校验。模型及输入预算须实测配置；
需要 OCR 的操作仅接受已验证的证照种类。能力与权限由服务端返回，前端不根据环境变量或按钮状态认定可用。

- 登录页使用受控账号和密码，提交中阻止重复请求；失败显示安全的错误或限流提示，不回显密码或泄露账号是否存在。
  登录成功重新检查目标资源权限；会话过期要求重新登录，不能靠恢复页面继续访问。

项目模式下，文档页签增加文件类型、保存版本和解析状态；“导入 Word”扩展为“上传资料”，

受理不表示解析完成。列表显示持久任务排队/处理/失败状态及快照真实覆盖/未覆盖；重解析不替换历史来源。
上传和重解析仅管理员/可编辑成员开放。DOCX 从所选已提交版本打开项目文档，页头显示项目和角色。

撤权拒绝后续操作并保留未保存修改，不以本地导出绕权。项目切换遵循工作区未保存保护，旧响应不进入新项目。

浏览器验收上传→排队→覆盖→打开→保存重开、冲突另存、只读/撤权；API 测试不代替 UI-14/UI-15 联验。

### 5.2 资料选择、事实准备与任务

任务页签提供已开放业务的类型选择及明确提交按钮。资料选择器展示名称、文件版本、
解析状态和覆盖范围；默认不把当前项目全部文件发给模型。默认选中当前文档也必须显示所选版本。
当前编辑有未保存修改时，先保存或明确选择已保存版本，不把页面临时文本作为无版本输入提交。
上传入口按产品规格 §10.5 记录来源和处理授权，展示实际支持类型、输入限制及必要的授权选择；
不因用户上传就默认取得所有外部处理权限。

事实准备与业务分析分为两次显式操作：

1. 选择项目内的文件版本及任务条件，查看本次解析覆盖范围；不可用材料不能进入正式分析。
2. “准备事实”提交独立持久化任务。完成后展示当前工作需要的字段，优先显示缺失、冲突和高影响项。
3. 更正时保留原值、来源、选用值和理由；事实性质、证据状态与人工确认状态分别展示。
   用户可保留待核实项，保存形成事实版本，准备任务不暂停等待该操作。
4. 查看本次输入清单，显式“开始分析”。清单包含文档/解析、事实、款项表、上游成果及
   服务端固定的规则/知识/模板版本；必要配置不齐时说明具体缺项。
5. 收到持久化任务 ID 后进入任务详情，刷新、离开或重开可继续查看同一任务。

从项目入口开始文书起草时，允许选用已有事实版本或保存人工录入的拟约定输入版本；
没有待提取材料时不提交空的事实准备任务，也不把拟约定输入当作已有材料事实。
按产品规格 §4.4 检查必需字段及来源门槛，缺失时只能形成对应草稿。
生成并保存文书成果后关联其结果版本及文书文件，不回写为用户上传原件。

整个工作区统一跟踪 Word 标题/正文、会话输入、事实更正、款项表、任务条件和成果修订的未保存状态。
切换右侧页签保留输入；离开、切换任务/文档/项目或成果版本前，列出本次将离开的所有未保存对象，
提供“保存并离开 / 放弃更改 / 取消”。“保存并离开”逐项保存可持久化对象，全部成功才导航；
任务条件仅保存为按用户和项目隔离的准备输入，不提交任务或发起模型调用。
任一保存失败或冲突都留在原工作区，保留未保存部分，已成功保存的独立版本不回滚、不重复创建。
“放弃更改”仅丢弃清单所列对象的未保存部分，不删除已保存版本或取消后台任务；取消保留全部输入和焦点。
事实/款项/成果的保存冲突按 §5.5 处理，普通 Word 冲突仍按 §4.2 另存；撤权后不得以离开保护绕过权限。
刷新/关闭窗口的原生保护也须由这些对象统一触发，不承诺恢复未保存的准备输入。

任务页在当前项目内默认列出输入清单关联当前文档的任务，可切换至本项目全部任务；未绑定文档时默认列出项目任务。
按提交时间降序显示业务类型、任务状态、提交时间和提交人，可按业务类型与任务状态筛选。
打开任务显示其关联文档和输入清单，不能将其他文档的结果冒充当前文档结果。
详情区分排队、处理中、成功、部分完成和失败，处理中显示真实阶段。
页面断线显示“状态获取失败”及重试，不将暂时无法获取状态改为任务失败或成功。
离开页面不取消后台任务，本轮不增加缺少服务端契约的“取消任务”按钮。

同一次提交重复点击或网络重发沿用同一幂等标识；响应不确定时先查询原任务，不立即创建新付费任务。
“重试”沿用原输入及累计预算，“新建分析”重新选择输入并创建独立任务，不能互相替代。
超过预算或时限后显示实际原因；重新消耗资源的新任务须明确告知用户并由其提交。

### 5.3 合同审查与来源定位

合同审查是首条接入流程。提交前确认专业分包人立场、合同双方、合同关系及可选辅助材料。
成果页签按付款、计量结算、工期、变更签证、违约责任、争议约定六类检查组织；
各类分别呈现发现问题、未发现问题、缺失条款、待核实或未覆盖，不用空列表代表“无风险”。

风险条目包含产品规格 §4.2 的字段；严重程度与资料充分性分列，法律依据、企业规则和招标要求
明确区分。支持按检查类别、严重程度及条目处理状态筛选，不把用户驳回的条目从历史中删除。
只有必要检查完成且输出有效时，才可显示“未发现问题”；所有候选均校验失败必须显示失败原因。

点击来源打开 Sheet，展示文件名称及版本、解析快照、定位信息、原文片段和引用关系。
PDF 使用页码，DOCX 使用标题路径/段落或表格行列，不虚构 Word 页码；图片展示原图、识别原值和更正记录。
法律依据或审查规则展示其已发布版本、条文/规则位置和适用条件，不伪装成用户上传文件片段。
来源对应旧结果时读取其原快照，不定位到最新文件中相似文字。缺失条款展示检查范围与规则，不伪造片段。
打开失败或无权访问时明确显示，不能标为本次读取或校验成功，也不能改用其他项目材料补齐。
暂时读取失败不改写保存版本的历史校验结论；重新校验发现引用失效时，按产品规格阻断相应复核和有效结论导出。
关闭详情恢复触发位置、列表滚动及键盘焦点，不改变当前编辑。

### 5.4 结构化成果与依赖变化

成果在专用表格、字段或章节区域查看和修订，聊天不是唯一入口。
机器原始结果、人工修订、条目处理状态、整份复核状态和任务完成状态保持可区分。
右侧页签切换保留未保存的字段和章节输入；切换成果版本或离开工作区前同样提供保存、放弃或取消，
不能因组件卸载而丢弃人工修订。
采纳、驳回或修订建议记录理由；这些操作不自动改写左侧合同原件，也不自动代表整份成果已复核。
需要据建议起草条款时，转入文书流程创建新的草稿，并显式选择上游保存版本。

输入资料、事实、款项或上游成果变化后，显示“基于旧版本”及变化对象的旧/新版本；
知识或规则更新显示“依据已更新”。用户可查看旧输入或开始新分析，旧结果和人工修订不自动刷新或替换。
成果历史可按业务类型、时间和复核状态筛选；打开历史版本与开始新任务具有不同操作入口。

### 5.5 保存、校验、复核与业务导出

人工保存基于明确的基础成果版本，成功后形成新版本、重新校验并恢复整份“待复核”。
保存成功不代表校验通过；校验失败的已保存版本可重新打开修订，但不能绕过对应业务门槛。
校验问题定位到条目或字段；保存冲突保留当前编辑，要求对照新版本处理，不静默覆盖。
Word 文档另存不能用来绕过业务成果的来源、关键金额或必需字段校验。
事实、款项表和成果保存冲突时，提供“查看最新版本 / 合并修订 / 取消”操作。
最新版本只读展示，不替换当前编辑；同时保留原基础版本和本次未保存修改，逐字段或章节显示差异。
用户明确选择合并内容后，以最新保存版本为基础建立新修订，再经保存、校验形成新版本。
未完成合并前不能仅替换基础版本 ID 原样重试；再次发生竞争时重新提示，继续保留当前修订。

“复核”针对整份明确保存的成果，读取同一版本的校验记录；有未保存修改时先处理修改，
不能把部分条目的采纳视为整份复核。无效引用、关键数值冲突及缺少必需字段不能通过复核按钮清除。
部分完成报告即使复核已有内容，仍显示部分完成和未完成事项。

业务“导出 DOCX”显示所选保存版本及复核状态；有未保存修改时，选择“保存后导出”
或“导出上次保存版本”，也可取消。服务端按产品规格执行导出门槛，不重新调用模型生成正文。
待核实、待复核及草稿标记保留在对应文件中；无效引用条目仅进入问题清单，不作为有效结论导出。
文书缺少必需字段时只能导出带明确标记的草稿。失败保留保存版本及已有导出文件，可重试所选版本。
只读成员只能下载已存在的导出，不能通过“下载”暗中创建新导出快照。

### 5.6 Agent 会话与操作边界

步骤三的会话区域按用户、项目和当前文档关联，展示真实任务事件和已保存成果摘要，
未绑定文档时按当前任务关联，并保留所关联的任务及版本。
事件只复述服务端实际状态，不生成额外法律结论，不默认读取整个项目或跨项目历史。
涉及提交任务、更新事实、保存修订或创建草稿时，使用明确操作入口，由用户确认版本与输入后执行。
业务处理结果以任务和成果记录为准，不以会话文本宣告完成。

本轮不开放独立自由问答，会话输入与发送按钮沿用 §4.3；运行结构化任务不自动启用普通消息发送。
独立问答须先在产品契约定义输入资料、模型上下文、调用预算、超时、权限、输出及失败验收，
本规格不以 UI 预留区授予该能力。会话发送不是结构化业务闭环的前置条件。
模型输出和上传材料按不可信内容呈现，不能授予任意网址、命令、权限变更、外部发送或覆盖人工内容的能力。
本轮不提供自动发送催款函、自动诉讼提交、开放式工具执行或实时协作。

### 5.7 业务扩展顺序

本轮按产品 §4.5「文档 Agent 网页增量」在现有右侧 Agent 面板内选择合同审查、款项核对或证据整理，沿用保存版本、授权、任务历史及结果展示。
款项与证据提交需核对截止日；地域仅为合同法律审查所需。两项资料整理不以待核对法律规则授权为前置条件，仍须确认材料外发。
不增加顶层业务 Tab；账号与项目界面仅保留 §5.1 的工作台宿主和切换器。合同的原审查与修订入口保持；资料整理结果不能调用合同修订导出。

文档 Agent 结果页提供人工修订与复核区：可修改款项金额/口径、证据事件性质与支持状态、缺口说明及催款函正文，保存为新的不可变版本；复核绑定明确版本，记录通过/驳回/退回修改及意见。导出区分机器结果、人工草稿和已复核版本；催款函复核通过后可下载已复核 Word。

各步复用同一套资料选择、任务、来源、保存、复核和导出交互，不另建四套页面。

| 顺序 | 界面交付与关键输入/输出 | 对应产品契约与验收 |
| --- | --- | --- |
| 1. 合同审查 | 六类检查、风险与充分性、来源、建议处理、审查报告 | §4.2；AC-03、AC-08—AC-13、AC-19、AC-21—AC-24 |
| 2. 款项核对 | 简化款项表按合同、期次、金额性质、本期/累计、单位及税口径录入；展示到期、扣抵、付款归属与来源；计算明细、争议及待核实项分列，口径不足仅输出草案 | §4.5、§8.3；AC-06、AC-19、AC-20 |
| 3. 证据整理 | 时间线、争点、证据对应表、缺口与有条件建议；沿用款项与事实保存版本，不将人工陈述显示为法院认定事实 | §4.5；AC-06—AC-09、AC-19 |
| 4. 催款函 | 显式选择事实、款项和证据成果版本及固定模板；逐项显示必需输入和来源；拟发送计划与已发生事实分开；编辑、校验、复核和草稿/完整成果导出 | §4.4；AC-05、AC-07、AC-11、AC-22 |
| 5. 补齐 Demo | 同模式接入专业分包合同、补充协议及投标材料核验；补充协议关联原合同；核验保留人工确认要求、材料检查及外部真实性两组状态和人工查询证明 | §4.3—§4.4；AC-04、AC-05、AC-14 |

证据整理沿现有任务与成果入口进入，不新增顶层业务 Tab；未绑定文档时仍可从项目材料选择。
成果页展示时间线、争点、证据对应表、缺证项与有条件建议，来源可定位到固定版本正文；页面与 Markdown 导出同一保存版本，并保留未核实、冲突和待关联标记。

三类文书仍限定专业分包合同、补充协议和催款函。步骤三最终保留四业务能力和三模板的 Demo 目标，
不因首条合同闭环完成就声明全部完成；共用权限、来源、修订与生命周期底线适用于每项业务。

## 6. 共用界面与可访问性检查

- 文案正式、简洁，只保留资源、操作及真实的错误、授权、校验和用户选择信息。
  不添加开发说明、预览标签或未完成功能装饰；业务草稿和未核实标记属于必要结果状态，不能删去。
- 页签、表格入口、按钮、对话框、Sheet 和面板调整均可用键盘操作；图标按钮具有可访问名称，
  焦点清晰且不被工具栏遮挡。关闭浮层后恢复到触发位置；不可只依赖悬停或颜色传达信息。
- 加载使用可读取的状态信息，错误关联具体操作或字段；后台刷新不反复播报整份列表和文档正文。
  关闭窗口的原生提示与应用内离开对话框分别验证。
- 至少验证 1440×900、1024×768、390×844 CSS px，以及 200% 缩放。
  应用外壳、操作和 Agent 输入不出现不可访问的溢出；Word 固定页宽可在画布内滚动，
  表格和来源原图可在各自容器内滚动，不强行压缩到不可读。
- 导航、异步响应及浮层绑定当前文档/项目和加载代次；旧响应不能恢复已关闭内容或污染新上下文。
  私有标题、正文、查询、输入和来源不写入跨用户共享缓存、公开 URL 或分析日志。
