# Word 文档编辑

## 1. 目标与范围

替换现有 Textarea，完成真正的 DOCX 新建/导入、编辑、保存、重开及导出闭环。
导出文件须由 Microsoft Word 实际打开核对；修改扩展名、HTML 包装或静态分页预览不属于完成。

本规格负责编辑引擎、DOCX 版本和文件往返验证。[工作台界面](02-workbench-ui.md)负责导航与会话布局；
[产品契约](01-product.md)负责项目权限、事实、来源、业务成果版本、复核和正式导出。
本规格负责单人编辑，不启用 Agent、OBS、多用户协作或法律业务材料处理。
服务端存储、SQLite / GaussDB 和远程部署由[数据库规格](04-database-deployment.md)扩展。

先支持普通中文段落、标题、列表和简单表格，并往返保留图片、页眉页脚、页码、域、修订标记、
文本框、批注、脚注/尾注、内容控件和合并表格等结构（保留能力以验证记录逐类别为准）。修订标记只保留、不编辑：不提供接受/拒绝、
不提供修订模式开关。旧版 DOC、加密文件、宏、扫描件、实时协作和任意复杂版式无损还原不进入本步承诺。
实际 DOCX 编辑与完整 Word 特性兼容分别验收。

## 2. 技术路线

采用 SuperDoc 1.x 浏览器引擎，通过 React 生命周期适配其官方构造器，不新增常驻文档服务器。
先验证最小文件往返、中文与表格，再连接应用存储；必要能力不通过时记录原因、修订选型，不能降为纯文本转换冒充通过。

2026-10-22 从 npm 官方元数据读取的验证基线：

| 依赖 | 版本 | 用途 |
| --- | --- | --- |
| `superdoc` | `1.47.2` | AGPLv3 浏览器 DOCX 编辑引擎，不含新版专有 `@superdoc/docx-engine` |

实施时核对精确版本、包内类型、资产和许可证，提交锁文件，不使用 beta、next 或不受约束的版本范围。
React 19.3 / Next.js 16.4 的兼容性须实际验证，peer 范围不替代构建和交互测试。
只安装本步需要的依赖，不因包暴露协作或 AI 接口就启用相关功能。

| 其他方案 | 已核对的差异 | 取舍 |
| --- | --- | --- |
| ONLYOFFICE Docs | 需要文档服务读取文件，应用提供编辑配置及保存回调，增加运行资源与信任边界 | 本步不增加独立文档服务 |
| Tiptap + Word Conversion | 富文本内核与官方 Word 转换分开，转换产品有独立接入和套餐边界 | 不以富文本内核替代 DOCX 往返能力 |

### 2.1 许可与 API 基线

SuperDoc 提供 AGPLv3 与商业许可。2026-10-22 用户明确选择项目按 AGPL-3.0 开源，根许可证采用 AGPL-3.0-only。
依赖、资产与第三方归属随制品保留；线上页面提供对应公开源码入口，镜像登记来源提交。
不购买许可证或接受额外商业条款。
CI 始终构建并验证镜像；GHCR 发布另需仓库变量 `WORD_EDITOR_DISTRIBUTION_APPROVED` 为 `true`。
只有完成上述许可与来源提供安排后才设置该变量；未设置时仍执行全部检查，但不发布镜像。

依赖核对发现 2.25.0 使用单独授权的专有引擎，故改用不含该依赖的 1.47.2，不安装官方 v2 React 封装。
官网当前指南为 v2；以精确安装的 1.47.2 类型、公开源码及测试为准，不混用 v2 参数。
导出保留文档内容，不把导出参数作为业务复核机制，不承诺未经验证的 PDF/HTML 导出。

## 3. 用户操作

### 文档列表与编辑

- “新建文档”创建可打开和导出的真正空白 DOCX，可使用受版本管理的最小空白模板。
- “导入 Word”只接收通过校验的 DOCX。同名文件有独立 ID，不相互覆盖。
- 列表从服务端已提交的存储读取，打开明确保存版本，不由纯文本重新拼装原文档。
- 现有页面内存草稿只有经用户明确选择才转换为新文档，不伪造原始 DOCX 来源。
- 左侧使用引擎官方文档画布与工具栏，右侧保留 Agent 会话。应用外壳、保存/导出和错误对话框使用官方 shadcn/ui 组件。
- 不自行重做 Word Ribbon，也不将引擎官方工具栏强行改造成 shadcn 控件；只适配容器、主题和响应式布局。
- 首批验证中文 IME、选择、复制粘贴、撤销重做、标题、段落、加粗/斜体/下划线、对齐、列表与普通表格单元格文字编辑。
- 页宽、页边距、分页和中文字体用实际文件核对。交付重点是导入内容往返保留；引擎自带工具栏操作不封锁，
  逐项冒烟并如实记录，未逐项验收的插入、批注、修订操作不声明支持。

### 保存与导出

- “保存”及 `Ctrl/Cmd+S` 将当前状态序列化为 DOCX Blob，存储事务成功后才视为保存成功。
- 标题与内容一起保存；下载时规范化文件名，只追加一次 `.docx`，不覆盖导入原件。
- “导出 Word”针对明确保存的版本；有更改时先保存，再下载这次保存的同一个 Blob。
- 无更改时直接下载保存字节，不再次生成正文、调用模型或序列化另一份不确定结果。
- 保存失败保留当前编辑，导出失败保留保存版本并允许重试；不能返回空文件或虚构成功。
- 序列化期间锁定引擎输入，核对正文文字未被导出操作改写，并比对 DOCX 正文文字与编辑快照。
  出现不一致时拒绝提交，恢复导出前的编辑快照；该核对不替代格式、分页和 Word 人工验收。
- 返回列表或切换文档前处理未保存更改，提供“保存并离开 / 放弃更改 / 取消”，失败时不自动离开。
- 刷新/关闭接入原生离开保护，但不能保证浏览器每次都显示提示，也不能以提示代替持久化。

不恢复“本地预览”“本地草稿”等装饰文案。真实的格式错误、保存失败和未保存更改属于必要操作信息，简洁、准确呈现。
工作台步骤一、二的 Agent 输入继续按文档隔离，发送保持禁用。
步骤三的应用侧任务事件及成果摘要按[工作台规格 §5.6](02-workbench-ui.md#56-agent-会话与操作边界)展示，发送仍保持禁用；
不启用编辑器内置 AI，不因会话发送而自行修改人工内容。面板、保存反馈和离开交互的 UI 验收由工作台规格负责，
本规格继续负责 DOCX 字节、引擎生命周期与 WD 验证。

## 4. 数据与版本

文档保存使用[数据库规格](04-database-deployment.md)定义的服务端接口和会话隔离。
历史 IndexedDB 数据继续保留，不自动上传；浏览器原数据、会话 cookie 与备份的边界记录在 README。

| 对象 | 数据与约束 |
| --- | --- |
| 文档 | 稳定 ID、标题、创建/修改时间、来源类型、当前保存版本 ID |
| 原件 | 导入时不可变的 Blob、文件名、摘要，不被人工编辑覆盖 |
| 保存版本 | 不可变 ID、父版本、DOCX Blob、摘要、时间、编辑器和模板版本 |
| 会话输入 | 独立关联文档 ID，不自动发送，不冒充材料事实 |

HTML、文本、编辑器 JSON 可以是派生数据，但不替代原件和保存版本的 DOCX 字节。
针对缺省样式或文档关系部件的合法最小 OOXML，仅在引擎工作副本补齐默认样式与关系；
保留原件与保存字节，不删除或改写正文，记录适配器版本。引擎异常后回退返回的原件不能作为保存结果。
人工编写、导入材料与后续模型/计算来源仍需区分。
当前版本指针与版本记录在同一短事务提交；序列化期间不持有存储事务。
保存携带文档 ID、基础版本和会话执行标识；重复触发不创建重复版本，迟到回调不写入另一份文档。
多标签页从同一基础版本保存须检测冲突，保留双方内容，不能静默以最后返回者覆盖。
发生冲突时允许将当前编辑“另存为新文档”，保留独立会话输入及源文档/基础版本关联，不覆盖其他标签保存的版本。

未来业务项目授权与 OBS 接入通过存储接口扩展，不提供公开文件 URL。
云端写入仍须重新核对成员权限、基础版本与内容摘要，不信任浏览器声明的授权。

## 5. 组件与生命周期

按实际实现建立以下边界，不预建通用编辑平台：工作区组件、浏览器 Word 引擎适配器、文档存储接口、DOCX 校验模块。
供应商 API 收敛在适配器内，不承担项目或法律权限判断。

编辑器在客户端动态加载，SSR/构建期间不得访问 `window`、创建 Worker 或读取文件。
正文不再由 Textarea 的 `content` 字符串驱动；标题修改和每次输入不得重建引擎。
就绪前禁用依赖引擎状态的操作，加载、序列化、保存和下载分别处理失败。

实例、事件及异步操作绑定文档 ID 和加载代次。切换前处理更改，之后销毁旧实例、解除事件、
撤销对象 URL、释放所拥有的 Worker；Strict Mode 重挂载不能留下重复工具栏或实例。
迟到结果先核对文档和代次，不覆盖当前新文档。第三方引擎实例不进入持久化对象。
日志只保留安全的错误类别与版本，不输出正文、文件字节、合同字段或私有 URL。

## 6. 文件与网络

沿用单文件 20 MiB、解压总量 100 MiB、最多 2,000 个包条目的上限。
校验扩展名、ZIP 类型、内容类型和主文档部件，限制路径、压缩膨胀及异常关系，拒绝加密、宏、ActiveX、OLE 和嵌套压缩内容。
校验失败先拒绝，不先交给编辑引擎，也不以静默删除部件的方式返回编辑结果。

普通段落、标题、列表和简单表格构成首批兼容性基线。内容结构不再在编辑器入口拒绝：
图片、页眉页脚、页码、域、修订标记、文本框、批注、脚注/尾注、内容控件、合并表格
（含复杂合并）一律放行，保留能力按验证记录逐类别声明，实测丢失的类别如实降级，不冒充通过。
格式变更修订（w:rPrChange）实测语义降级：元素往返保留，但变更前属性状态的负值写法（w:val="0"）被引擎规范化，Word 实开不识别为修订；插入、删除、移动修订完整保留。证据见 docs/reviews/2026-10-27-docx-structure-roundtrip-validation.md。
安全类继续拒绝：宏/ActiveX、OLE/嵌入对象、外部资源与外链模板、`altChunk`、嵌套压缩、加密与超限包。
导出核对口径：正文按同一提取契约精确相等（计入 `w:t`：表格、文本框 Choice 分支、修订插入文字、
域结果；不计入 `w:delText`、moveFrom、`w:instrText`、`mc:Fallback`、页眉页脚/批注/脚注部件文字）；
结构数量导出不得少于编辑快照（图片、修订标记、批注、脚注引用、文本框、合并单元格），
不一致即拒绝提交并保留当前编辑。
编辑器可显示与业务解析、审查的覆盖范围分开，不因能显示而宣称已分析。

不自动获取文档外链、远程图片或外部模板。默认关闭协作、网络拼写检查、供应商 AI 和其他文档外发。
按安装版本显式关闭遥测，并用网络记录验证。
引擎、Worker、样式和允许的字体固定版本、同源部署。私有文件不进入 `public/`，空白模板不得包含敏感数据。
CSP 仅放行所需资产和经验证的 Worker 机制，不以关闭安全保护换取可用。

加载/校验初始超时 60 秒，支持取消并回到列表。先验证 1—20 页代表样本，再按产品上限验证 100 页与 100,000 字符边界。
上限不是未经测量的性能承诺。浏览器校验不替代未来上传 API 的服务端校验和解析隔离。

## 7. 实施与验收

顺序为精确依赖/资产/许可核对 → 最小 DOCX 往返 → 中文/表格/分页 → 替换 Textarea → 本地版本保存 → 异常与容器验证。
失败时修复或调整支持范围，不以占位工具栏计为完成。

| 编号 | 通过条件 |
| --- | --- |
| WD-01 | 新建真正空白 DOCX，输入中文、编辑标题、保存重开后内容一致 |
| WD-02 | 导入合成合同、修改指定条款，导出后 Word 与网页重开均有修改 |
| WD-03 | 标题、文字格式、对齐和列表在支持样本中往返一致 |
| WD-04 | 简单表格修改、中文字体和分页通过 Word 文件核对，无内容丢失 |
| WD-05 | 返回、切换和刷新后能重开保存版本；导入原件摘要不变 |
| WD-06 | 保存/导出失败、取消离开、配额不足不清空当前编辑 |
| WD-07 | 迟到回调、快速切换、Strict Mode、多标签冲突不覆盖其他文档或较新版本 |
| WD-08 | 导出字节与明确保存版本一致，旧版本保留，下载可重试 |
| WD-09 | 损坏、伪装、超限和不支持文件按预定条件拒绝，无静默删改 |
| WD-10 | 打开/编辑/保存/导出无未授权外网请求，遥测和外部处理确已关闭 |
| WD-11 | 代码、类型、生产构建、Docker 资产与桌面/窄屏交互通过 |
| WD-12 | 实际依赖与资产许可、分发路径和第三方声明有记录，未擅改项目许可或购买授权 |
| WD-13 | 往返样本逐类别（图片、页眉页脚、域、修订标记、文本框、批注、脚注、内容控件、合并表格）经 导入→编辑→导出 后由 Microsoft Word 实际打开核对，结构与文字按预期清单一致，保留/降级结论如实记录 |
| WD-14 | 导出核对拦截静默丢失：正文不一致或结构数量少于编辑快照时拒绝提交、保留编辑、可重试；正常编辑（含删除内容）不误报 |

样本涵盖中文、样式、列表、表格、分页、重复编辑和异常文件，使用合成或明确授权资料。
下载文件由 Word 实际打开；只使用其他 DOCX 编辑器时记录产品与版本，不声称 Word 验证已通过。
WD 是编辑器接入验证，不计入法律业务准确率分母，也不自动使 AC-02、AC-10、AC-11、AC-15 或 AC-16 通过。
