# EquiLens saurlax：项目平台与其余新增业务开发 Plan

> 负责人：丙；任务编号沿用总计划，不重新编号。本文只分配开发任务，不表示实现或验收通过。
> 本文件拥有 C 组详细任务及进度；[总计划](2026-10-27-three-person-development-plan.md)拥有共享契约、跨人依赖、全局约束和共同发布门槛，避免两处重复维护任务状态。

**Goal:** 向主线提供有授权、可追溯的项目资料平台，并完成投标核验、其他两模板及项目生命周期。

## 1. 职责、前置与交接

负责 C1—C7；不重复实现审查 Agent、款项算法、催款函、共享事实仓储或任务执行器。规范库管理页面遵守 C6 的先修订规格边界。

建议分支：`saurlax/project-and-other-modules`。每个工作包独立提交和审查，保留他人改动，不自动提交、推送、创建 Issue 或部署。

| 交接对象 | 丙接收 | 丙交付 |
| --- | --- | --- |
| 甲 | 账号身份、编辑器访问接口、任务/预算、成果/导出及迁移编排 | 项目授权守卫、私有资料/来源服务、项目 Word 适配、对象/生命周期恢复清单 |
| 乙 | 共享事实/更正接口、核对后的主线规则、催款函模板与校验 | 可选保存版本、解析快照/覆盖、历史来源、规则及三模板仓储 |

优先 C1 → C2 → C3，先交项目授权、资料来源与项目 Word 通路，解除主线依赖；然后推进 C4/C5。C6 P0 规则发布接入与 C7 生命周期随相关仓储同步实施。OCR 未验证时继续其他独立开发，不提供虚假识别成功。

开工前阅读[规格索引](../../../spec/README.md)及任务拥有规格；现行约束见[总计划 §2](2026-10-27-three-person-development-plan.md#2-全局约束)，文件所有权见[§4](2026-10-27-three-person-development-plan.md#4-目录与集成所有权)，接口草案见[§5](2026-10-27-three-person-development-plan.md#5-共享交接契约与依赖)。这些接口仍是实施草案，行为缺规格时先更新拥有规格再实现。

## 2. 详细开发任务

### C1 项目、成员、主体关系与工作台宿主（P0）

**文件：** 拟新增 `src/server/projects/{repository,authorization,service}.ts` 及测试、`src/app/api/projects/`、`src/components/business/platform/project-switcher.tsx`；修改 `src/components/workbench.tsx`。

- [ ] 在甲 A1 身份上实现三角色与当前成员判定，只有管理员管理自己有权项目成员；账号维护不下放为项目管理权限。
- [ ] 保存实际当事人、合同和合同关系，不因甲方/乙方推断立场；项目来源授权、目的/期限与生命周期元数据同时入库。
- [ ] 切换项目前走 A2 未保存登记，切换后撤下旧视图并取消旧请求；迟到响应不能重现前项目资料。
- [ ] 测试两个项目/三角色/资源 ID 伪造、只读借重试写入、撤权后领取/外发/下载拒绝；每个业务入口重新鉴权。
- [ ] 运行 `pnpm exec tsx --test src/server/projects/*.test.ts`，与 A5 完成真实 GaussDB 首闭环；无实例可交付 SQLite 技术结果但不关闭真机项。

**交付标准：** 乙可在已授权项目运行主线，甲可在领取和预算预留事务调用授权守卫；AC-01/15、UI-14。

### C2 私有资料、OBS、DOCX/文字 PDF、来源服务（P0）

**文件：** 拟新增 `src/server/storage/obs.ts`、`src/server/materials/{repository,service,parse,sources}.ts` 及测试、项目资料 API 与预览组件；复用现有受限解析模式。

- [ ] 上传前登记来源、处理授权、目的和期限；按真实类型检查大小、压缩/活动内容/外链及资源限制。业务可解析范围与 Word 可编辑范围分别判定。
- [ ] 接入私有 OBS，持久化对象与内容摘要；失败残留对象有受限回收，不开公有桶或长期公开链接。
- [ ] DOCX/文字 PDF 解析形成不可变快照及原文片段，保留阅读顺序/表格定位；重解析不覆盖旧引用。
- [ ] 输出覆盖清单：混合扫描、关键嵌图、不支持结构不得显示全面处理；未验证 OCR 不当作已提取全文。
- [ ] 提供历史来源和下载服务；原件/版本/快照外键归属一致，服务端重查授权，临时读取失败不改写历史验证记录。
- [ ] 运行 `pnpm exec tsx --test src/server/materials/*.test.ts src/server/storage/*.test.ts`；真实 OBS 私有读写及文字 PDF 新输入单独留证。

**交付标准：** 乙拿到稳定版本、原文和覆盖，A4 可以验证引用；AC-02/08/09/21/24/25、UI-15/18。

### C3 项目 Word 读写适配（P0）

**文件：** 拟新增 `src/lib/business/documents-client.ts`、`src/server/materials/editor.ts` 及测试，项目 Word API；消费甲的 `editor-access.ts`。

- [ ] 将项目 open/preflight/save/copy/download 接到项目授权与 OBS 资料版本，不复用匿名 owner、contextId 或匿名期限。
- [ ] 同 operationId 返回同版本，baseRevision 冲突不覆盖，复制保留来源，未提交 OBS 对象不能成为分析输入。
- [ ] 下载所选保存版本的同一字节；只读/撤权不挂可编辑引擎，不借保存失败后本地导出绕过权限。
- [ ] 运行 `pnpm exec tsx --test src/lib/business/documents-client.test.ts src/server/materials/editor.test.ts`，实际浏览器验证保存重开/冲突/离开及项目切换迟到响应。
- [ ] 联同甲回归匿名版本：匿名资料清理不删除重新导入的独立项目副本。

**交付标准：** 项目文档产生的新版本可供 B1/B2 选择；AC-09/10/12/15，相关 WD 和 UI-14/15。

### C4 OCR 与投标材料核验（P0，C2 后接入）

**文件：** 拟新增 `src/server/verification/{requirements,ocr,repository,service,validation}.ts` 及测试、`src/components/business/platform/verification-form.tsx`；OCR 云适配放在服务端边界。

- [ ] 在真实账号实测后声明可支持证照类型；保留原图、识别原值/置信信息、人工更正和请求用量，不用桩结果代替 OCR。
- [ ] 从所选招标/补遗版本提取要求候选，保留原文、主体、要求性质、字段、比较、条件及判定时点；漏提和无依据新增否决条件计入质量结果。
- [ ] 人工对照来源采纳/更正/驳回候选，保存要求版本后再确定性比较；任务不暂停等待人工，不直接用候选否决资格。
- [ ] 支持已约定单层 AND/OR；嵌套、性质/时点不明或补遗冲突转人工，不新增复杂表达式平台。
- [ ] 材料一致性/完整性和外部真实性两组状态分开；未查到/失败不显示核验通过，人工核验保存来源、时间、条件、操作者和证明。
- [ ] 运行 `pnpm exec tsx --test src/server/verification/*.test.ts`，覆盖到期/主体不符/缺件/模糊识别/补遗冲突/查询失败及跨项目拒绝；封存并实跑投标 6 个独立案例。

**交付标准：** AC-04/14/17/21/24，UI-23；没有可用权威 API 时使用有证据的人工路径，不臆造自动接口。

### C5 专业分包合同、补充协议及模板仓储（P0）

**文件：** 拟新增 `src/server/templates/{repository,service}.ts`、`src/server/drafting/{service,validation}.ts` 及测试、`src/components/business/platform/drafting-form.tsx`。

- [ ] 与乙共同固定三模板的 ID、版本、必需字段、来源门槛和渲染入口；仓储由丙维护，催款函内容和校验由乙维护。
- [ ] 实现专业分包合同、补充协议的固定模板和有限生成；补充协议显式关联原合同版本，不扩展任意合同起草。
- [ ] 空项目可保存人工拟约定输入版本后起草，不先建空白 Word、不提交空事实准备任务、不把拟约定当材料事实。
- [ ] 缺质量/工期等必填项、原合同关系或关键证据时保留草稿；生成文件关联成果版本，使用 A4 修订/校验/复核/导出。
- [ ] 运行 `pnpm exec tsx --test src/server/templates/*.test.ts src/server/drafting/*.test.ts`；独立文书 4 例与乙催款函 2 例合为文书 6 例，三模板均有齐备/缺项反例。

**交付标准：** AC-05/07/11/19/22，UI-23；模板升级不改变旧成果和旧导出。

### C6 已发布知识/规则接入与规范库边界（P0/P1 分开）

**文件：** 拟新增 `src/server/knowledge/{repository,publication,service}.ts` 及测试；乙提供现有 `rules/` 内容及核对记录。

- [ ] P0：建立受控发布仓储/私有维护入口，保存知识/规则版本、原始来源、适用条件、核对人/时间、停用及摘要；发布规则包优先于补充关键词取材。
- [ ] P0：任务固定发布版本，停用内容不进入新任务；未核对资料在正式模式拒绝，更新只提示旧结果依据变化，不重写旧输入。
- [ ] P0：运行 `pnpm exec tsx --test src/server/knowledge/*.test.ts` 及乙的 pack/scenes 回归；验证假签核、未发布和跨目录/跨项目读取拒绝。
- [ ] P1：规范库可视化维护先修订工作台规格 §3 当前“暂无规范、本轮不支持上传/编辑/发布”的边界，明确角色、输入、发布失败、历史和验收后再实现；不凭本计划直接开放上传。
- [ ] P1：若纳入已修订范围，按权限提供发布资料列表/检索/历史及管理入口，保持官方 UI 模式；若未接受该范围，保留当前空状态并如实登记未交付，不影响 P0 受控业务规则发布。

**交付标准：** 主线和投标只调用已发布适用版本；本计划不把规范库管理页面冒充现行已接受 Demo 必需功能。

### C7 项目保留、私有对象清理与完整恢复（P0，随仓储实现）

**文件：** 拟新增 `src/server/projects/lifecycle.ts`、`src/server/materials/retention.ts` 及测试；维护 `docs/deployment.md` 项目对象/恢复说明并交甲合并。

- [ ] 原件、快照、事实、任务、模型产物、成果、导出及证明附件均纳入项目保留/删除清单；不因不可变而无限留存。
- [ ] 项目删除撤销访问并记录可恢复备份所需删除记录，回收失败保留记录/重试；不影响独立匿名或其他项目副本。
- [ ] 按产品 §10.4—10.5 配置异地备份、保留和删除重放，不替用户指定真实项目目的/到期日。
- [ ] 准备对象清单/摘要、版本引用和恢复顺序；与 A5 在新环境实际恢复数据库、私有对象、配置及最新删除记录。
- [ ] 邀乙核对旧报告来源、人工修订、三模板旧文件、事实/款项版本和在途任务；验证已删项目不复活。
- [ ] 运行 `pnpm exec tsx --test src/server/projects/*.test.ts src/server/materials/*.test.ts` 并保留真实恢复日志。

**交付标准：** AC-16/25 的完整项目证据；只恢复数据库行或下载一个新文件不能通过。
