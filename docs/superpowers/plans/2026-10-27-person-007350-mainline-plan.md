# EquiLens 007350：合同审查到催款函主线开发 Plan

> 负责人：乙；任务编号沿用总计划，不重新编号。本文只分配开发任务，不表示实现或验收通过。
> 本文件拥有 B 组详细任务及进度；[总计划](2026-10-27-three-person-development-plan.md)拥有共享契约、跨人依赖、全局约束和共同发布门槛，避免两处重复维护任务状态。

**Goal:** 贯通“合同审查 → 款项核对 → 证据整理 → 催款函”，支持新资料真实处理、人工复核和版本化导出。

负责 B1—B5，拥有事实与主线业务语义；不另建登录、项目权限、存储、任务执行器、成果仓储或通用导出服务。

建议分支：`007350/collection-mainline`。每个工作包独立提交和审查，保留他人改动，不自动提交、推送、创建 Issue 或部署。

| 交接对象 | 乙接收 | 乙交付 |
| --- | --- | --- |
| 甲 | 认证、编辑器未保存登记、任务/模型预算、成果修订/复核/导出 | 事实/主线结构和校验器、任务类型需求、工程故障复现 |
| 丙 | 项目成员授权、资料版本/快照/来源、项目 Word 保存、发布规则及模板仓储 | 共享事实及更正接口、主线规则核对记录、催款函模板与校验 |

立即开始 B1 的事实模型、案例与标注准备，同时实现 B3 的纯金额计算和 B2 的离线业务校验。正式联调依赖甲 A1/A3/A4 和丙 C1/C2/C3；按 B2 → B3 → B4 → B5 贯通，不能用匿名联调冒充项目业务完成。

开工前阅读[规格索引](../../../spec/README.md)及任务拥有规格；现行约束见[总计划 §2](2026-10-27-three-person-development-plan.md#2-全局约束)，文件所有权见[§4](2026-10-27-three-person-development-plan.md#4-目录与集成所有权)，接口草案见[§5](2026-10-27-three-person-development-plan.md#5-共享交接契约与依赖)。这些接口仍是实施草案，行为缺规格时先更新拥有规格再实现。

## 2. 详细开发任务

### B1 主线事实、分析清单与独立案例（P0，立即启动）

**文件：** 拟新增 `src/server/facts/{repository,service,validation}.ts` 及测试、`src/components/business/mainline/{fact-editor,input-manifest}.tsx`；维护 `docs/reviews/business-step-three-demo-case-designs.md` 的主线案例。

- [ ] 固定事实键：主体/合同、字段含义、时间/期间、单位及会计口径；区分材料事实、人工陈述、更正、拟约定及计算事实。
- [ ] 实现独立“准备事实”任务，结束后人工更正另存版本，保留原值/冲突/理由；确认不消除证据冲突。
- [ ] 分开“准备事实”和“开始分析”，明确资料/解析、事实、款项、上游成果、规则/知识/模板版本；未保存 Word 先保存或显式选已保存版本，不默认发全部项目。
- [ ] 对接 A2 未保存登记、A3 任务入口及 C2 来源；原件/事实变化形成新版本并保留旧结果读取。
- [ ] 准备合同 8 例、纠纷 4 例、催款函 2 例的独立原件和预期；邀请实际领域核对人签核后封存，不把案例槽位当材料或标注完成。
- [ ] 运行 `pnpm exec tsx --test src/server/facts/*.test.ts`，覆盖同名不同主体/期间、陈述不冒充事实、冲突、竞争保存和跨项目拒绝。

**交付标准：** 丙可复用事实版本；缺证和正常输入均能表达。规则、预算或云服务未就绪时继续离线技术开发，正式分析入口保持受控。

### B2 正式项目合同审查闭环（P0）

**文件：** `src/server/contract-review/index.ts`、`tools/contract-review/src/`、`rules/`、`skills/`、`src/components/contract-review-*.tsx`，拟新增 `src/components/business/mainline/source-sheet.tsx`。

**前置：** C1/C2/C3、A1/A3；完整闭环还依赖 A4。甲只处理工程故障，业务语义修改由乙负责。

- [ ] 固定专业分包人立场、双方、合同链、地域、时间和辅助资料；适用条件不足保留待核实，不从正文推断角色。
- [ ] 复用 Agent 及固定编排，形成六类必检与明确 coverage；空报告、全部校验失败、部分读取和真正无风险分别输出。
- [ ] 与领域核对人核对法律版本/条件、企业规则和引用；经 C6 发布仓储保存签核和版本。现有 debug 规则未经签核不能改标 published。
- [ ] 来源 Sheet 使用 C2 服务读取固定历史快照；DOCX 用段落/表格行列，PDF 用页码；缺失条款展示检查范围而不造引文。
- [ ] 实现类别/严重程度/处理状态筛选、采纳/驳回理由、人工修订、重验/复核和报告导出，不自动改合同原件。
- [ ] 先运行 `pnpm test:contract` 及相关任务测试，再以当前提交、真实模型、正式资料版本做已授权新合同端到端；记录用量、原始输出、拒绝项、漏检和误报。

**验收：** UI-17—UI-20/22，AC-03/08/09/10/11/13/21/22/24；正常、缺条款、缺证、冲突、文档诱导和全部无效案例均有明确预期。

### B3 款项核对（P0）

**文件：** 拟新增 `src/server/payments/{amount,ledger,calculate,validation}.ts` 及测试、`src/components/business/mainline/payment-ledger.tsx`。

- [ ] 用十进制字符串接收人民币并严格转换整数分，禁止 Number 浮点金额路径；定义材料来源、到期条件、范围、累计/本期、付款分配和扣抵字段。
- [ ] 保存款项表及人工更正版本；未确认的候选金额不进入确定净额，模型仅提候选，不决定计算结果。
- [ ] 区分计量值、净到期应付、已付、未到期和争议主张；重复付款去重，已计入净额扣项不再扣减。
- [ ] 确定性验证示例：计量 1,000,000 元、已核实到期比例 80%、同口径已付 300,000 元、无其他扣项时，到期应付 800,000 元、未到期 200,000 元、已到期未付 500,000 元。
- [ ] 验证付款大于到期额保留负值；累计/本期不明、付款归属不足、扣项争议、缺到期证据仅形成核对草案；利率/起息日缺失不得补造。
- [ ] 运行 `pnpm exec tsx --test src/server/payments/*.test.ts`；通过 A4 保存/重验/复核/导出，并验证旧输入版本可重算。

**验收：** AC-06/19/20，UI-21；正常与反例均精确到分，未到期/争议金额不伪装成确定债权。

### B4 证据整理与纠纷成果（P0）

**文件：** 拟新增 `src/server/evidence/{service,validation}.ts` 及测试、`src/components/business/mainline/evidence-view.tsx`。

- [ ] 显式选择事实/款项版本和文件快照，生成时间线、争点、证据目录、支持/冲突和缺口；人工陈述有独立性质。
- [ ] 对每项事实和争点保存来源关系，缺送达/验收/到期证明显示具体缺口，不把法律意见写成已认定事实。
- [ ] 款项或原件变化提示旧版本，不静默重排或重写人工证据成果；复用 A4 并发合并、复核和导出。
- [ ] 运行 `pnpm exec tsx --test src/server/evidence/*.test.ts`，覆盖缺证、冲突时间、重复附件、跨项目引用、旧来源及人工修订保护。

**验收：** AC-06—AC-10/19，UI-18/20/21；新资料形成可追溯证据成果，不能以“有一张表”代替纠纷业务验收。

### B5 催款函与主线全流程（P0）

**文件：** 拟新增 `src/server/collection/{service,validation}.ts` 及测试、`src/components/business/mainline/collection-form.tsx`；催款函模板内容提交 C5 的模板仓储。

- [ ] 固定债权主体、合同、到期条件、金额、收件主体及发送计划等模板字段和来源门槛；显式选合同/款项/证据保存版本。
- [ ] 材料不足、主体不明、关键债权只有陈述、金额冲突时仅形成明确草稿，不用“已人工确认”绕过证据门槛。
- [ ] 发送计划不冒充已完成送达；不增加自动外发。生成文书关联成果版本，不伪装成上传原件。
- [ ] 经 A4 完成人工编辑、保存重验、复核及 DOCX 导出；修订不被重试或新分析覆盖。
- [ ] 运行 `pnpm exec tsx --test src/server/collection/*.test.ts`，另做一套新输入“审查 → 款项 → 证据 → 催款函”浏览器演练及 Word 核对，记录耗时和操作数。

**验收：** AC-05/07/11/17/19/20/22，UI-21/22；材料齐备和关键缺证两条主线均符合预期，不重复录入已有版本事实。
