# 第三轮：业务交互接入实施计划

> 执行者：按任务顺序实现，每项独立验证和审查；本文件是实施计划，不是新增产品契约或验收记录。
> 当前仅完成计划编写，不执行实现，不创建 GitHub Issue，不自动提交、推送或部署。

**Goal:** 基于现有 DOCX 工作区及匿名审查联调，交付按项目授权、具有不可变来源和人工修订保护的业务闭环，先完成合同审查，再补齐 Demo。

**Architecture:** 保留单个 Next.js 应用和现有 Word 引擎；新增账号/项目业务边界，复用数据库连接、解析子进程及审查核心。业务解析、事实准备、分析和导出使用同一个数据库持久化、进程内串行调度入口；匿名数据及其删除生命周期保持独立。

**Tech Stack:** Node.js 24、pnpm 11.6.0、Next.js App Router、TypeScript、SQLite / GaussDB、官方 shadcn/ui、SuperDoc 1.47.2、既有 AI SDK；私有 OBS、MaaS、经实测的 OCR 通过 server-only 适配器接入。

## 3. 全局约束

- 单应用、Node.js runtime、首版单实例；无独立 Worker、Redis、向量设施或额外队列服务。
- 使用 Node.js 24 与固定 pnpm 11.6.0；仅维护 `pnpm-lock.yaml`，保留 SuperDoc 固定版本及许可安排。
- 私有数据不进入共享缓存；凭据不入客户端、Git、截图和日志；Route Handler 保持薄。
- 项目三角色及撤权覆盖页面、API、来源、原件、历史、下载、任务领取及每次外发。
- 匿名资料仅由用户导出后重新导入获授权项目，形成独立副本并重新登记来源/授权；匿名清理不得删除项目副本。
- 文件接收默认：文档 20 MiB、图片 4 MiB、PDF 100 页、每任务最多 10 份；DOCX 100,000 字符、总提取 200,000 字符。模型预算单独实测，不静默截断。
- 解析默认 60 秒/512 MiB 子进程；默认单任务累计 600 秒、最多 3 次 Attempt、心跳 15 秒/租约 60 秒。固定流程最多 3 次模型请求，审查 Agent 使用单独的累计请求预算、可信配置最多 25，证照最多 2 次 OCR；不得混淆或恢复后清零。
- Demo 容量目标为 5 个已登录交互用户、全局 1 个执行任务、最多 10 个排队任务、每用户最多 2 个未终结任务；批量解析的最多 10 份文件按同一父任务计数。容量须实测，超限明确拒绝。
- 请求次数、模型上下文和费用额度分别限制；付费外发前校验任务与项目已登记预算并持久化占用，额度不足或未登记不发送。未知费用保守占用，恢复不清零；预算/告警由负责人依实际账号价格登记。
- RMB 使用整数分或精确十进制；数据库和 JSON 边界不得经过浮点金额转换。事实区分材料支持、人工陈述、拟约定和计算派生。
- 人工保存形成不可变版本，每次重验结构、来源、关键数值、必需字段并重置整份复核状态。复核不能消除缺证/冲突；导出不调用模型。
- 界面保留文档/规范库、Word/右侧 Agent；来源临时 Sheet；使用官方组件，无开发说明装饰或模拟成功。
- 任一任务发现现有 spec 无法确定行为，先修改拥有该行为的 spec，明确输入输出、失败、权限和验收后再实现；计划中的建议文件名不是已接受的数据/API 契约。

所有私有引用携带项目归属，关联在服务端和数据库约束中双重校验；新解析、新分析或新模板均创建新记录，不替换旧记录。

## 6. 依赖、执行批次与暂停条件

```text
1 契约/外部前置 → 2A 认证 → 2B 项目授权/双数据库首闭环 → 2C 项目宿主
→ 3 资料来源 → 3A 项目 Word 适配 → 4A/4B/4C 统一任务 → 5 事实准备
→ 6 合同审查 → 7 修订/复核/导出（M1）
→ 8 款项/证据 → 9 催款函及三模板（M2）→ 10 投标核验
12A 随任务1启动 → 12B 各模块首轮 → 12C 冻结/容量
11 完整恢复/平台与评测并行准备 → 12D 修复回归/证据汇总（M3）
```

首个执行批次为任务 1—4（含 3A），并同时启动 12A，完成后审查 M0，再开始合同业务界面。M0 的项目 Word 读写、队列/费用准入及任务 2B 的真实数据库验证逐项留证；缺项保持未验收，不阻止不依赖该项的 SQLite 技术开发。
生命周期、正反例测试、领域核对和研发证据随各任务推进；每个业务闭环完成立即进入 12B 首轮，不能等待全部四业务或任务 11 完成才测质量。任务 11 与 12D 汇总最终验收。
现有编辑器未影响业务路径的验收缺口可以补测并行推进；影响保存、冲突或来源读取的回归必须先修复。

| 条件 | 继续工作 | 阻断内容 |
| --- | --- | --- |
| 领域规则/法律来源未核对 | 合成资料、结构/来源校验及权限开发 | 正式法律结论与完整业务发布 |
| 模型预算/发送目标未实测 | 离线测试、资料/版本界面 | 正式 AI 提交 |
| 私有对象、项目权限或来源不可验证 | 基础实现和隔离测试 | 真实项目资料处理及对外业务开放 |
| OCR 或云平台不可用 | 不依赖该服务的已验证流程 | 对应能力验收及完整 Demo 声明 |
| GaussDB 首闭环缺真机证据 | SQLite 技术开发及接口测试 | 2B 数据库兼容性、完整 M0 及对应平台验收 |
| 费用预算未登记/不足、队列超限 | 已有资料/成果的获授权访问及非付费检查 | 新付费外发或超限任务提交；恢复不绕过 |
| 发现必须改变已接受范围 | 先更新所属 spec 并明确验收 | 受该变更影响的实现 |

以上是实施/发布闸门，不构成新的用户审批流程。未决实施任务留在本计划供审阅；需要持久跟踪时另经授权建 Issue。
