# 合同审查可靠性与成本调整

目标：场景停止可重选、报告计数一致、下载版本明确、成本可追溯、关闭模型全文仍可恢复。
沿用匿名文档权限、单应用串行任务与不可变输入；不修改规则发布状态或队友的登录/云服务实现。

1. 场景：`schema.ts`、`service.ts`、`agent/router.ts`、`pipeline.ts`、`cli.ts`、任务面板；先测失败→新任务→适配通过/拒绝及跨会话拒绝，再实现。
2. 样本/计数：TXT 唯一源生成 DOCX；`presentation.ts`/报告组件/测试验证互斥计数与路由。
3. 下载/端点：仓储/HTTP/client 区分任务 ID 与未生成；双客户端离线兼容测试与显式合成 smoke。
4. 成本：三档模型固定输入、内容哈希资源缓存、公共提示/schema 装配；不合并独立复核，不改批次/预算；固定夹具比较实际 calls/tokens/耗时。
5. 留存：独立 usage 摘要与可选全文，旧记录兼容、恢复和累计预算测试；文档列出规则核验清单及队友接口需求。

按各组针对性测试验收，再运行 pnpm check、pnpm test、pnpm build、git diff --check。真实模型仅合成输入、保留固定上限并记录实际失败，不虚报其他端点/法律准确率/UI 人工验收。
