# 复核输出截断的降级处理

日期：2026-10-28。分支：`fix/audit-truncation`。

## 问题

任务主审完成后停在 partial，复核 0/19；界面报“模型输出达到长度上限，本批结果未采用”。

根因不是累计 token 预算，而是独立复核的单次输出：

- 复核按 3 条规则一批提交；
- 每批 `maxOutputTokens` 只有 8,192；
- 真实合同里一批的核对说明/引文/推理超过上限，`finish_reason=length` 后整轮复核停止，前面的主审结果被保留但没有复核意见。

## 已改

- 复核单批输出上限从 8,192 提升到 16,384。
- 批次仍被 `length` 截断时，不再终止整个任务：
  - 自动把批大小降为 1；
  - 从当前批第一条未复核规则重新开始；
  - 已接受的复核意见保留；
  - 单条仍截断时才停止并保留 partial。
- 复核预算预留增加 1 次调用，给降级重试留出空间。
- 报告中的长度/预算错误改为用户可读文案，并收进“检查进度与技术详情”折叠区；未完成数量只在顶部汇总。

## 测试

- 新增合成 transport：3 条批返回 `length`，单条批返回合法意见；验证最终 `completed`、6/6 复核、批次从 3 降为 1。
- `tools/contract-review/tests/audit.test.ts`：8 项通过。
- `pnpm check` 通过。
- 全量 `pnpm test` / `pnpm build` 结果见提交说明。

## 边界

- 这是重试降级，不保证单条请求永不截断；单条仍失败时保留 partial，并允许继续原任务。
- 没有改变规则发布状态、项目权限或云端配置。
- 真实模型仍需用长合同复测；合成测试验证的是控制流和预算预留，不代表特定供应商的稳定延迟/输出。
