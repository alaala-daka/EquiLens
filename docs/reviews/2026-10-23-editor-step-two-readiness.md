## 静态核查发现

以下来自本次实际读取代码，不是新执行的运行测试结果。

| 位置 | 当前基础 | 本步需要处理 |
| --- | --- | --- |
| `document-editor.tsx` | 保存、导出、冲突另存、离开对话框、快捷键、beforeunload、会话预检 | 单一 busy 混合保存/导出；缺独立保存状态；保存重试每次生成新 operationId；快捷键需与按钮共享冲突/就绪守卫 |
| `word-canvas.tsx` | 动态加载、60 秒超时、输入锁、正文比对、工作副本与销毁 | 异常只回传文字；就绪状态不能完整传到外壳；缺有保护的重新加载；异步超时后的底层导出不能视为已经结束 |
| `workbench.tsx` | 按文档 ID 挂载编辑器、保存更新列表、会话变更撤下旧编辑器 | 接入新控制器时保留这些边界；权限失效不经离开对话框重新授予访问 |
| `use-mobile.ts`、`ui/resizable.tsx` | useSyncExternalStore、768 分界、现有官方面板包装 | 在真实浏览器核对方向切换、键盘调整、长标题和窄屏操作可达；不靠重建引擎切换方向 |
| `serialize.ts`、相关测试 | 回退原件、空 Blob、超时、正文检查已有保护 | 新行为继续覆盖这些保护；补超时迟到和新操作重叠的验证，不把旧测试存在当作新回归通过 |
| `client.ts`、服务端仓储 | 会话错误与修订冲突区分、明确版本、operationId 幂等 | 复用现有 HTTP 和数据库契约；预检不能用较新服务端字节替换用户选定的保存版本 |

实施重点是补齐现有闭环，不重写编辑引擎或服务端文档模型。Agent 输入仍按文档保存，发送禁用。
不新增登录、项目、业务任务、自动保存、历史版本浏览、格式兼容承诺或云服务接入。

## 方案选择

1. **推荐：聚焦编辑会话控制器，复用现有画布与服务。**把操作阶段、重复提交、冲突和迟到响应移出 JSX，
   用现有 Node 测试工具验证；组件保留布局、焦点和生命周期组合。变更集中且可独立审查。
2. 继续在单组件增加布尔状态。文件改动少，但冲突、引擎故障、离开和保存重试的组合难以验证。
3. 更换引擎或增加通用状态/测试框架。引入迁移与许可、字节往返回归成本，超出本步必要范围。

计划采用方案 1；这是实现拆分建议，不增加产品行为或新的外部依赖。
