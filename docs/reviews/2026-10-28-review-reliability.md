# 审查可靠性与成本调整验收

日期：2026-10-28。分支：`feat/agent-polish`。范围只覆盖合同审查 Agent；未改规则发布状态，未扩账号/项目/云服务。

## 已落地

1. **场景停止后手选**
   - schema 接受已登记场景 + 原失败任务、理由和服务端时间。
   - 服务端校验原任务归属、失败状态、同一文档/保存版本和有效期；新任务保留原任务。
   - 网页任务卡片提供“手动选择场景后新建审查”；CLI 固定场景共用 `checkSceneApplicability`，不再直接进主审。
2. **样本与计数**
   - TXT 为唯一样本源，DOCX 由脚本生成；两者均 18 段，自动路由测试通过。
   - 报告按规则 ID 互斥计数：总数 = 问题 + 无问题 + 未完成 + 被拒绝/未定位。
3. **成本与重复输入**
   - 路由/主审/复核三档模型配置，未配置时回落 `AI_MODEL`；任务固定实际模型。
   - 规则包、技能和场景组合按内容 SHA256 缓存，返回隔离副本；文件内容变化即失效。
   - 主审公共提示和工具 schema 在模块级复用，不合并独立复核，不改批次/预算。
4. **端点与下载**
   - `pnpm ai:compat` 对当前配置实际跑通 `askModel` 与 `ToolLoopAgent`；离线覆盖正常、截断、空内容、refusal、缺 usage、工具信封、空参数和非 JSON 参数。
   - 原审查任务 ID 下载修订稿返回 `409 REVISION_TASK_REQUIRED` + 经双任务鉴权的 `revisionTaskId`；无子任务/未生成返回 `REVISION_NOT_READY`，前端由用户打开目标，不自动下载。
5. **模型全文留存**
   - 每次响应先写 `model-summary`（哈希、模型、usage、耗时、结束原因、工具名），`full` 模式另写全文。
   - 预算从摘要累计；同一调用的摘要和全文不重复计数；旧 `model-exchange` 记录兼容。
   - 表单“模型与保留说明”显示当前全文/摘要模式及保留天数。

## 成本对照的边界

同一份 `sample-contract.txt`、同一 `deepseek-flash` 的历史记录（2026-10-25）为 19 次、218,552 token。当前记录为 19 次、184,177 token：

- **调用次数没有下降**；本轮没有合并主审/复核，也没有改批次。
- token 差异来自独立模型运行、提示/schema 复用和随机输出，不能证明因果，也不代表账单金额。
- 本轮 CLI 没有记录可靠的总耗时；不填猜测值。

因此第 3 组完成的是“可配置、可缓存、可追溯”，不是“调用次数已降低”。如果下一步要降调用，应单独设计主审批次合并并做同输入前后对照，不能拿本轮数据冒充优化结果。
