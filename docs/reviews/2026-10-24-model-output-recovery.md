# 模型异常结束处理修复

## 现场证据

本地最新失败任务：69 段、19 条必检规则，第 8 次实际请求报 `AI_OUTPUT_INCOMPLETE`。
前 7 次读取技能、目录、正文、来源及搜索正常；没有有效提交，结果中保留 19 项待核实。
该任务占用 8/25 次调用、约 51 秒累计执行时间。
只读检查本地 SQLite，未修改任务、预算或模型配置，没有重新外发合同。

旧传输层先拒绝异常结束，再调用请求/响应留存钩子，导致第 8 次响应没有保存。
因此无法回溯断言此次属于长度截断、模型拒绝还是其他结束原因，不补造响应。

## 修复

契约：[架构 Agent 入口](../../spec/00-overview.md#合同审查-agent-的增量入口)。

- 每批最多 3 条结论；提示每回合只提交一次，必要引文保留完整条件，全部必检项仍须处理。
- 有界、可解析的 JSON 响应先保存后检查，私有留存包括失败响应，不保存密钥/请求头。
- 分开处理长度截断、拒绝/内容过滤和其他异常；不执行不完整工具参数。
- 每次 Agent 尝试最多对长度截断修正一次，在原上下文提示只调用一个工具、提交时只交一条。
  修正重新进行外发前权限与预算预留，计入原次数及时限；再次截断、拒绝及其他异常不继续重发。
- 保留此前有效结论、未答项和每次响应可核对的用量；失败响应保存失败则停止。
- 全部规则已有效提交后直接停止 SDK 循环，避免额外调用模型生成不用于报告的自由总结。
- 旧任务的输入、规则和技能快照不替换；「继续原任务」沿用其确认输入、预算及到期时间。

## 验证

Windows / Node.js 24.16.0 / pnpm 11.6.0；全程为合成响应，没有真实模型调用。

- `pnpm test`：204 项，203 通过，1 项原有 Linux 文件/目录 fsync 检查在 Windows 跳过。
- `pnpm check`、`pnpm build`、`git diff --check`：通过；未部署或发布镜像。
- 实际 SDK 工具循环验证：分批接受、截断后一次修正成功、再次截断保留部分结果、
  修正前预算预留失败不外发、一次尝试跨回合最多修正一次、失败响应保存与用量累计。
- 拒绝/过滤和未知原因不自动修正；无效工具参数不执行；没有把无效回答变成无风险。
- 初次静态检查发现测试中的 PromiseLike 与 Node assert.rejects 类型不兼容，改为异步函数适配。
