# 主审调用与 token 控制

日期：2026-10-26（Asia/Shanghai）。阶段：Demo 授权联调。基线：`b3871a3`；本地改动未提交、推送或部署。
契约：架构「新任务主审材料准备与成本边界」、产品 §4.2.1；关联 AC-03、AC-09、AC-21、AC-23、AC-24。

## 原因与改动

用户任务的17次调用中，主审13次：技能1次、目录2次、正文2次、依据1次、分批提交7次；主审累计187920 token。两次修订又因思考占满8192输出而截断。这是实际任务诊断，仅查看本地记录，没有重新外发用户文档。

新网页任务固定 `primaryStrategy=prepared-v1`：

- 场景确定后程序准备技能、完整解析正文、本批规则和允许来源，取消模型准备调用。
- 同一个主审按六类处理，每批最多四条，每次建立独立上下文；只带未完成规则和本批拒绝原因，已接受结果保存在检查点，不带前批完整回答或思考。
- 保留完整正文，不用关键词裁去跨条材料。正文/提示超限明确停止；只有有效模型响应后记录交付范围、输入摘要，逐条校验引用、来源及适用条件。交付记录不证明模型理解。
- 工具定义在各批保持稳定，规则范围由服务端再次限制；正文位于批次变量前以利前缀缓存。缓存是否命中按上游 usage 实测。
- 截断改为单项新上下文，仍计入原预算；单项继续超长则停止。JSON/字段错误提供明确的短反馈，不把原始SDK异常或完整失败回答塞回提示。
- 新任务主审/修订分别固定 default/low 配置，默认 low，旧任务不变。任务配置、来源及策略摘要变化拒绝混用恢复结果。
- 修订另固定 `revisionStrategy=prepared-v1`，按未处理问题锚点分批，发送本批主审/规则/来源、原全文和已保存修改映射；不用包含全部原审查与工具历史的长对话。继续检查原文、关键值、规则范围及不可覆盖的已接受修改。
- 改后合同核对固定 `auditStrategy=prepared-v1`，保留完整前后正文，原主审、处理说明和来源限定本批，映射只含位置/规则关联，不重复正文。无效项单独拒绝并反馈，同批有效核对保留，原覆盖及导出门槛不变。
- 默认250000已记录累计 token 停止阈值；发送前从任务全部尝试的不可变交换记录汇总用量，达到阈值停止下一次外发。失败和缓存命中用量不被扣除，恢复不重置。

该阈值不是供应商预扣：最后一个响应可能超出，未返回 usage 的请求用量未知；默认25/最大40次及累计600秒仍有效。所有请求仍经过会话/权限、租约和执行令牌校验。未达到外发预留的拒绝不增加角色调用计数，已持久化但中断的预留继续由数据库保留。

## 真实合成对照边界

只使用仓库 `scene-mep-contract.txt`，与前次成功合成任务比较同一解析正文摘要和模型。先保存预期、25次调用上限、250000已知token阈值及测量字段，再执行；测试数据库和保留日志均隔离在 `.superpowers/`。不发送用户业务合同，不修改其任务、环境配置或开发数据库。

首次新策略测试6次请求、27858 token、约49秒后因格式纠正失败停止，没有 Word：模型给「缺失条款」附带补充引文被拒，下一次工具JSON格式错误没有形成可用反馈，随后重复错误。保留全部有效项和失败记录；此结果不能算作完整审查节省。已补明确的缺失条款格式约束及SDK无效参数反馈，并增加复现测试；随后另做一次有界合成验证，不因法律质量结果自动反复抽样。

第二次新策略测试18次请求、257334 token、约125秒后触发已记录 token 阈值；19项主审和修订说明完成，但只核对4/19项，没有 Word。主审7次/37967 token，对照旧合成样本为11次/122270 token；修订仍消耗199224 token，成为主要开销。阈值按预期阻止下一次外发，没有提高预算续跑。由此进一步给修订加入独立批次与本批材料装配，并保留第二次结果，不能把未完成的整流程当作成功节省。

第三次网页任务主审6次完成，随后在16次累计请求/109922 token时停在18/19项修订说明。最后一项反复把pending与editIds混用，校验正确拒绝，但反馈不够具体。补充明确反馈后，只对保存的合成检查点做离线库级续跑；它没有更新原网页任务或数据库，也不作为网页重试成功证明。沿用原累计次数、用量及剩余时限，累计24次/255427 token时再次被阈值阻止，修订19/19、核对16/19，仍没有Word；没有扩大预算追加最后一批。

这次定位到改后核对仍重复携带全部原审查、修改全文和来源，一条坏引文还使整批重做。随后增加上述精简核对及有效项保留，并用合成回归验证原覆盖、引用和新问题阻断不变。阶段性低用量均不能视为完整成果的节省；完整对照以最终独立合成验证为准。

## 使用与恢复

重启 `pnpm dev` 并刷新页面后提交新任务。旧任务「继续原任务」保留原工具循环、原思考和预算，不能在恢复时偷偷改为新策略。已保存 Word 仍读取原字节。

服务端配置：`AI_PRIMARY_REASONING_EFFORT`、`AI_REVISION_REASONING_EFFORT` 和 `AI_REVIEW_MAX_KNOWN_TOKENS`；详见 `.env.example` 与网页操作说明。不支持推理参数的服务会明确失败，部署者应验证能力后选择 default/low；不静默替换模型或扩大预算。
