# 四场景合同修订与 Word 建议稿

日期：2026-10-26（Asia/Shanghai）。阶段：Demo 授权联调。基线：`b3871a3`。改动保留在本地，未提交、推送或部署。

契约：产品 §4.2.1、Word §3.1、工作台匿名合同审查及架构任务边界。关联 AC-03、AC-09、AC-11、AC-20、AC-21、AC-23、AC-24；不作为法律业务验收。

## 实现

- 明确选择生成修订稿后，按「场景识别 → 主审 → 修订正文 → 独立核对改后合同」执行。普通审查和历史任务保留原流程。
- 新增机电安装、装饰装修、幕墙、钢结构四个修订技能，均为 `0.1.1-draft`。技能按场景固定绑定，连同规则、来源及输入版本保存。
- 修订只提交原文逐字绑定的段落替换或正文插入；未修改文字、表格位置、原件和人工版本保留。原无问题项保留，原待核实项继续待确认，全部原规则仍进入独立核对。
- 关键值检查拒绝未经确认的金额、比例、期限、机构及主体变更。无效项单独拒绝，保留同批有效内容；缺少处理说明、孤立修改、无效引文和新问题均阻断导出。
- Word 在资源受限子进程生成并再次校验，保存不可变字节及摘要。下载重新核对会话和保留期限，读取保存字节，不调用模型或重新生成。
- 页面默认展示三处主要修改、需确认事项和 Word 下载，其余修改、全文、核对详情和原审查按需展开。机器核对不改变人工审核状态。

界面依据：[官方 Blocks](https://ui.shadcn.com/blocks)、[Collapsible](https://ui.shadcn.com/docs/components/radix/collapsible) 及[示例源码](https://raw.githubusercontent.com/shadcn-ui/ui/main/apps/v4/registry/new-york-v4/examples/collapsible-demo.tsx)。延用现有组件和样式，无新增依赖、自定义 CSS 或动画。

### 浏览器、下载和重新导入

- 第三次从真实网页组件发起任务，经过实际会话、上传、数据库、任务执行器和外部模型；浏览器下载的 Word 摘要与保存制品相同，重复下载字节相同，原版本摘要保持不变。
- 测试脚本随后重新导入时漏传保留授权，接口正确返回 `422 RETENTION_CONSENT_REQUIRED`；这一步未通过。脚本已补齐参数，没有因此重跑模型。

## 本地使用

在仓库根目录运行 `pnpm dev`。打开已保存的基础 DOCX，在合同审查中保留「生成合同修订稿，并核对修改后的合同」，确认地域、联调依据和外发授权后提交。成功保存后使用「导出修订建议稿（Word）」；需要编辑时将建议稿作为独立文档导入。

已有开发服务应先重启，以加载更新后的后台流程及技能。旧任务不自动生成修订稿。模型失败、超时、预算耗尽或核对仍存在问题时保留结果并阻断导出，不用展示文案替代成功制品。
