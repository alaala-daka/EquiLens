# 不支持结构文档的“仅保留正文另存”

日期：2026-10-28。分支：`fix/unsupported-docx-clean-copy`。

## 问题

用户新建/编辑的 DOCX 在保存时会重新导出并校验。若正文含图片、页眉页脚、域、修订、文本框、批注、脚注或合并单元格等当前未验证结构，校验器会拒绝保存并显示：

> 文档包含暂不支持的图片、页眉页脚、域、修订或复杂结构。

这不是保存按钮或权限故障。空白文档和长空白文档都能正常保存；失败发生在编辑结果重新打包后的 DOCX 校验。

## 已实现

- 保存/导出失败且错误为“不支持结构”时，错误条显示“仅保留正文另存”操作。
- 点击后先弹出确认，明确说明图片、页眉页脚、域、修订、文本框、合并单元格等格式会丢失，原文档及版本不变。
- 用户确认后：
  - 从当前 ProseMirror 快照提取顶层段落；
  - 用空白 DOCX 重建仅含正文的 DOCX，做 XML 转义并重新通过 `validateDocxBytes`；
  - 通过现有 `createDocument` 以 `copy` 来源创建独立副本，`copiedFrom` 指向当前文档/保存版本；
  - 打开新副本，标题追加“（仅正文副本）”。
- 不静默删除结构、不覆盖原文档；取消不产生任何写入。

## 验证

- 单元测试：XML 转义、空段落、段落数量/文本校验、顶层段落提取。
- 浏览器真实流程：新建空白文档 → 粘贴含 `colspan` 的表格 → 保存被拒绝 → 点击“仅保留正文另存” → 确认 → 新文档打开且已保存，标题为“未命名文档（仅正文副本）”，无警告。
- 数据库核对：原文档 `authored` 版本仍保留；新文档 `source=copy`，`copiedFrom` 指向原文档/版本。
- `pnpm check` 通过；`pnpm test` **350 项：349 通过、1 平台跳过**；`pnpm build` 通过。

## 边界

- 该操作是**有损降级**：只保留正文文字和段落，不保留格式、图片、页眉页脚、域、修订、表格合并等。
- 仅当保存/导出错误包含“暂不支持”时显示；其他保存失败仍走原错误处理。
- 没有自动清理原文档；用户可自行保留或删除（删除入口不在本功能范围）。
- 未支持结构的来源可以是粘贴或导入；本功能不尝试识别具体标签，只做显式人工降级。
