# 网页合同审查与任务交接

## 使用

1. 根目录安装锁定依赖，登记 ANONYMOUS_DATA_RETENTION_DAYS；在忽略的 `.env.local` 填写 AI_BASE_URL、AI_MODEL、AI_API_KEY。
2. `pnpm dev` 自动打包 DOCX 子进程解析器，Node.js instrumentation 启动任务执行器。
3. 导入基础 DOCX，或打开已有文档；修改后先保存。
4. 在右侧「合同审查」选择是否生成合同修订稿，确认代表专业分包人、地域、发送目标、记录保留时长及外发授权；不预选项目场景。
5. 解析后独立场景 Agent 识别合同。普通审查由主审及独立复核处理；选择修订稿时，主审后加载本场景修订技能，再由独立 Agent 核对修改后的整份合同。未匹配时停止，关闭页面不取消任务。
6. 点击引文查看任务固定版本的解析原文。取消阻止后续调用；继续原任务不重置预算或期限。

网页目前只接 DOCX，TXT 继续走 CLI。当前会话隔离不是账号/项目成员授权，丢失 cookie 后不能凭任务 ID 取回资料。
已有未保存更改不会被发送，当前编辑器和原件不因任务自动变化。修订稿是独立建议稿，仍需人工审核。

当前登记房建机电安装、装饰装修、幕墙、钢结构四类专业分包，均为授权联调。场景识别必须核对适用性，
不能从甲乙方称谓推测客户代表哪一方；立场由用户在提交前确认。
识别结果保存理由、原文证据及固定目录，报告检查进度中的「场景识别依据」可展开定位。未匹配时不显示空风险摘要。
识别、主审及独立复核共用原请求预算及累计时限；主审预留复核预算，恢复复用已完成角色和已保存选择。
候选目录更新会改变配置确认摘要，旧任务和旧报告保留原目录。开发更新后重启服务，后台 runner 才使用新代码。
自动识别接口提交 `context: { scene: "auto", role: "专业分包人", region: "上海" }`；不接受前端直接指定场景绕过识别。
现有显式场景 CLI/后端及存量任务保持原流程。普通新审查固定 multi-agent-v1，生成修订稿固定 multi-agent-revision-v1；四个资源包和修订技能摘要随任务保存，恢复不替换规则。
网页默认只做审查；勾选「生成合同修订稿」才进入修订与改后核对流程，调用次数和 token 约增加 2–3 倍（实测一份 2,129 字合同的纯审查约 5.4 万 token，含修订约 25.8 万）。
装饰装修、幕墙和钢结构各增加三条专项清单，与19条通用检查组合；专项清单为合成联调资料，不能继承发布资格或作为强制法律结论。
独立复核在报告中称为「AI 复查」；首页提示未完成或需人工核对数，详细数量、意见及未复查项在检查进度中展开查看。主审原件保留；机器保留不是人工复核通过。

报告首页显示问题数、类别数和必要的初步结果提示，随后依次为「优先处理的问题」「需要进一步确认」「尚未完成的检查」。
每类默认展示一项问题与修改方向，「查看本类其余 N 项问题」查看剩余独立结论，
「展开原文、解释与依据」查看完整问题、建议、影响、来源核对状态、固定版本引文与该项 AI 复查意见。
长预览带省略号，原始记录不变。重复的共性调试声明不计为客户待确认事项，只在报告末统一提示；
具体事实或依据疑点仍保留，原文相同的待确认事项合并展示，并在详情保留关联规则。
后端占位、未定位及未获有效回答的检查项单独统计，失败、未覆盖和范围不完整仍提示。
「展开检查进度与停止原因」保留覆盖、规则编号、实际错误、警告及「原始待核实记录」。
旧报告的整段已知声明仅在展示时归类，不改写 JSON，不重发合同；未知或混有具体疑点的文字保守保留。
普通审查使用精简表达要求，不默认生成替换条款或自行填入谈判参数；旧任务只改变展示，
不会自动重新生成或收费。CLI 的 Markdown 报告采用相同层级，JSON 保留完整记录。
后端可拦截明确编号、相邻删除/保留动作与唯一争议方式的矛盾；这是局部检查，不能保证全部建议正确。

### 合同修订建议稿

网页默认勾选生成修订稿，也可取消，仅运行原审查。API 用 `generateRevision: true` 明确请求该流程，省略仍为普通审查。
四个修订技能分别对应机电、装饰装修、幕墙、钢结构。原未发现问题与待核实项由程序保留，模型只修订其余原问题；全部规则仍由独立上下文针对改后正文核对。

审查完成后也可不勾选修订，先做纯审查；在报告中勾选需要修订的问题（发现问题/缺失条款），再生成仅修订任务。该任务固定原主审快照与所选规则，不重新识别场景或运行主审，只修订并核对所选规则；未选规则保留原审查结论，未修改段落由程序按原快照重建并在导出前校验。报告与 Word 标注本次范围，所选规则全部核对且无存在问题项才可导出。
成果首页先显示原审查问题、风险和建议；相关原文、修订建议及待确认内容在对应问题展开。完整修改对照及检查进度仍可查看。只有 Word 已保存且核对完整、没有存在问题项时提供「导出修订建议稿（Word）」。
独立建议稿可将明确对应的原有金额、比例、日期或期限改为待确认标记，同时记录原值、原文位置和标记；未经确认不得补造新的确定值，主体信息不能自动改动。具体机构或谈判参数缺失时保留待确认标记或原文。基础数值/单位校验及机器核对不等于法律正确性和人工审核。
正文和简单表格替换保持未改部分及单元格位置；新增段落只允许正文锚点。待改段落含书签、链接等未验证结构时拒绝生成，不静默丢弃。
制品带 AI 建议稿标记和待确认事项，随任务保存固定字节、摘要、来源版本及渲染版本。下载不触发模型或重渲染。可作为独立 DOCX 再导入编辑；不会自动覆盖当前文档。
复杂任务可能耗尽预留预算；保持部分结果及失败信息，不以新请求重置原任务计数。需要新分析时重新确认输入、配置及外发授权。规则及模型仍处于联调，不能当作正式业务验收。

### 新任务的主审成本策略

新网页任务固定 `prepared-v1`：程序按已选场景提供技能、完整解析正文和本批规则/依据，主审首次调用即开始判断。按六类规则、每批最多四项使用独立上下文，不携带前批完整回答和工具历史；只补做未接受项。19 项常规清单的目标为六次主审请求，截断或拒绝可能增加调用，不保证固定成本。

完整正文超出提示预算时明确停止，不按关键词删除正文。缺失/无问题仍要求完整解析和全文交付，引用及适用条件继续校验。每批记录交付范围和输入摘要；该记录不证明模型理解或法律正确性。

主审和修订默认低思考，配置随任务保存；不支持参数的服务会明确失败，部署者应核实服务能力后设置 default/low。新任务默认在已记录累计总 token 达到600000后停止发送下一次请求，最后一个响应可能超过阈值；缺 usage 为未知，不代表免费。它不是人民币硬预算，缓存输入仍计入 token。审查面板会显示当前已记录 token 和停止阈值。

策略、模型配置和 token 阈值变化需要重新确认新任务；旧任务继续原流程，不自动重跑或变更预算。

正文修订另固定 `revisionStrategy=prepared-v1`，按未处理问题的原段锚点分组，独立请求只带本批原审查/规则/来源、原合同全文和已保存修改映射。已有修改不可覆盖；跨批同段无法安全补改时保留待确认，由独立核对判定，不用减少来源校验换取导出。

修订稿核对固定 `auditStrategy=prepared-v1`，保留完整修改前后正文，按本批限制原审查、处理说明和来源。修改映射提供位置及规则关联，不重复复制正文。单项无效只重做该项，同批已接受意见保留；全部原规则核对完成且没有存在问题项才可导出。

旧工具循环每批提交最多 3 条结论；prepared 主审最多 4 条。单次输出仍限 8192 token，分批不减少必检项。
截断、拒绝/内容过滤和其他异常结束分别报错；有界 JSON 失败响应也保存在私有任务记录中，
不执行其中未完成的工具参数。长度截断每次尝试最多修正一次，要求本回合只提交一条；
修正仍经过权限和预算预留。prepared 主审超长时改为单项新上下文；单项仍超长则停止，不无限缩批或续写。拒绝及其他异常不自动重发；已有结论、调用次数及可核对用量保留。
全部规则已有有效提交后由后端结束循环，不另调模型生成总结。
修复前未留存的失败响应不能补造；界面历史错误保持原记录。需要再次处理时使用「继续原任务」，
按实际剩余次数、时限及保留期限执行；开发环境更新后重启 `pnpm dev`，确保后台执行器使用新代码。

## 配置

| 配置 | 含义 |
| --- | --- |
| AI_REVIEW_MODE | 后端固定 published/debug；开发默认 debug，生产默认 published |
| AI_REVIEW_RETENTION_DAYS | 任务及派生记录固定保留天数，1–365；开发默认 7，生产必配 |
| AI_REVIEW_MAX_PROMPT_CHARS | 单次完整序列化请求上限；调试默认 240000，正式模式须显式配置经验证的值，范围 1000–240000 |
| AI_AGENT_MAX_CALLS | 原任务累计请求上限，默认 25，可配置 1–40，跨重试/恢复不清零 |
| AI_AUDIT_REASONING_EFFORT | 独立复核的 default/low 配置，默认 default；low 仅用于已验证支持的模型服务，随任务固定 |
| AI_PRIMARY_REASONING_EFFORT | 新任务主审 default/low，默认 low；旧任务不变 |
| AI_REVISION_REASONING_EFFORT | 新任务正文修订 default/low，默认 low；旧任务不变 |
| AI_REVIEW_MAX_KNOWN_TOKENS | 新任务已记录总 token 停止阈值，默认600000，范围10000–2000000；跨尝试累计，非供应商硬预扣 |

内置规则尚未发布，published 模式会拒绝提交。debug 必须在网页明确确认未核对资料，报告保持该标记。
模型地址和名称在提交时固定，运行时仅从环境读取密钥；更换密钥不需要把凭据存入数据库。
生产需要常驻单实例 Next.js Node.js 容器及持久数据库，不使用会随请求结束退出的 serverless 任务运行方式。

## 代码与接口

- `src/server/contract-review/tasks/`：配置、输入固定、任务仓储、受限 JSON 处理、执行器。
- `src/instrumentation.ts`：明确 Node.js 生命周期启动，不在模块导入或构建时启动执行。
- `src/lib/contract-reviews/`：共享线类型及浏览器请求。
- `src/components/contract-review-*.tsx`：表单/轮询、任务历史、报告与引文定位。
- `tools/contract-review/src/agent/pipeline.ts`：独立路由、场景主审及可恢复复核；router.ts / audit.ts 各自拥有隔离工具。
- `tools/contract-review/src/bundles.ts`：场景规则/来源/技能装配、摘要与发布隔离。

## 后续增加功能

- 增加审查规则或依据：更新 `tools/contract-review/rules/`；专项规则位于 rules/scenarios/，调整对应 skills/ 下操作说明并同步规格、版本与验证。
- 增加新的业务流程（如款项核对、证据整理）：新增对应 skill，并补齐所需工具、服务端校验、任务数据/API 和页面；跨业务共用的能力做成工具。
- 新功能涉及保存数据、权限或结果格式时，先更新 `spec/` 中对应约定，再改代码和交接文档。Skill 负责告诉 Agent 怎么做，不能代替权限、计算和结果校验代码。

| 接口 | 行为 |
| --- | --- |
| GET /api/contract-reviews?documentId=… | 本会话任务摘要、服务端配置和确认摘要；不返回合同全文 |
| POST /api/contract-reviews | 携带 Idempotency-Key；白名单版本/条件/配置确认/外发授权，202 返回入库任务 |
| GET /api/contract-reviews/[id] | 本会话详情及有效阶段结果/最终报告 |
| GET /api/contract-reviews/[id]/revision | 本会话、有效期限内读取已保存 Word 修订建议稿；不生成新内容 |
| POST /api/contract-reviews/[id] | action=cancel，或 action=retry 且重新确认 externalProcessingConsent=true |

写入同源检查，响应 private,no-store，参数和密钥不上前端日志。重复 key/同输入返回原任务，变化输入返回 409。
所有请求携带 X-Document-Context；成功响应回传相同上下文，浏览器在解码和显示前检查，错误沿用文档会话 code。
取消只撤销后续处理，不承诺已到模型服务的请求可撤回或不计费。

## 存储与恢复

独立 `equilens_review_schema` 版本不改文档 schema。tasks 保存输入/规则/技能/模型快照、授权、固定期限、
状态、令牌/租约、累计预算、解析快照、检查点和最终结果。artifacts 保存各尝试的原始模型请求/响应和结果。
请求产物不包含 Authorization/header；内容仍可能包含合同材料，必须作为私有资料备份。
任务外键绑定同 owner 文档和版本，原资料清理会级联清理审查及产物。

全局 runner 行租约保证串行领取，心跳 15 秒、租约 60 秒。跨进程恢复须等旧租约过期；
每个任务最多 3 次尝试、累计 600 秒。网络/超时/5xx 最多自动重新尝试一次；限流等待用户操作，不自动紧循环。
请求预算发送前事务预留，失败和不确定的请求也占用次数，不等同于精确账单。
恢复复用解析快照和有效结论，新模型重新读取用于后续提交的正文和依据；旧尝试不能写回当前结果。
阶段结果与终态在短事务中保存，解析/模型不在事务内运行。到期立即拒读/执行/外发，后台清理任务及派生物。
SQLite 备份包含上述表；恢复后按当前到期时间守卫，完整项目/法律业务恢复尚未验收。

任务复用主分支的数据库、会话仓储和删除日志就绪屏障，保持独立任务 schema。
事务内检查上下文及 read/review 权限；领取、解析和每次预算预留均重新检查。
到期取审查期限与原会话期限的较早值；只读导出窗口可读取已有结果和取消，不允许提交、重试或外发。
缺少 documentContextId 的旧任务不能恢复外发，需重新确认后提交新任务。已有文档不会自动登记期限，
存量仍须按部署说明通知、登记并完成导出窗口处理。

## 历史实现检查范围

`node node_modules/typescript/bin/tsc --noEmit --incremental false` 通过；首次发现配置 mode 推断问题，修正后通过。
按用户要求，没有运行测试、构建、浏览器、数据库迁移/恢复或真实模型请求。
UI 采用官方 Blocks 目录和 Tabs 示例，沿用现有 Resizable 工作区；无专用审查 block，使用已有官方组件组合。
审查授权的原生 checkbox 为语义表单控件，无额外定制视觉样式。没有新增组件依赖。
整合后的实际检查以[主分支整合验证](reviews/2026-10-23-contract-review-main-integration.md)为准。

界面组合参考官方 [Collapsible 组件示例](https://ui.shadcn.com/docs/components/radix/collapsible)；沿用既有组件和工作台布局，将修订信息嵌入对应问题，未使用自定义样式。模型连续两次未产生有效修改时，该批未关联已接受修改的问题保留原文并标为待确认；预算、独立核对和导出闸门不变。

新任务在独立核对发现问题且剩余调用次数足够一次修正及完整再核对时，最多启动一次定向修正；记录原稿、原核对、尝试状态和使用量。修正成功后对新稿重新核对全部规则；仍有问题或修正无效则停止，不能导出。中断后不重复已登记的修正请求，旧任务按原策略恢复。token 阈值按已记录用量在每次请求前检查，并非对下一次模型输出的预扣保证。
