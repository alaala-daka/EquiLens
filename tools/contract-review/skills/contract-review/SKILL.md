# 专业分包合同审查

## 适用条件

审查立场为专业分包人，项目为房建机电安装专业分包。只使用调用方确认的主体关系、项目类型和地域。
不从甲方/乙方猜测法律角色，不把未知条件视为满足。条件不明的规则返回待核实。
本技能为操作说明，不是法律依据。正式结论只引用本次允许的、已发布且已核对的规则及来源。
调试模式使用待核对资料时保留调试声明，不形成正式法律结论。

## 步骤

1. 通过 parseDocument 查看当前固定解析快照的目录、完整性和段落编号。目录按游标分页读取。
2. 按本次提供的全部规则检查六类事项；不能自行省略规则，不能用关键词未命中证明条款不存在。
3. 用 searchDocument 找线索，再用 readParagraphs 读取完整正文。搜索预览不计为已读。
4. 遇到“按第某条执行”、补充条款、扣款或验收条件时继续补读相关段落，核对条款间的矛盾。
5. 用 readSources 读取相关规则允许的依据，确认适用条件。企业规则、合成示例与法律依据分别对待。
6. 用 submitFindings 每批提交 1–3 条结构化结论，每回合只调用一次提交工具；不要先积攒所有规则的答案。
   用 checkCoverage 查看未答规则，继续处理或明确待核实；引文保留必要完整片段，不重复整段合同。

## 必检事项

- 付款条件与时间：时间、比例、前提、上游回款约束、验收和扣款条件。
- 计量结算：计量口径、确认流程、结算时间、争议和逾期处理。
- 工期：起止条件、延误责任、顺延和通知程序。
- 变更签证：发起与授权、确认程序、计价和时限。
- 违约责任：触发条件、责任范围、扣罚与重复承担。
- 争议约定：解决方式、机构/管辖约定及适用条件。

具体判断以 loadSkill 返回的规则为准。区分法律风险、商业不利和信息不明，不把不利约定自动认定为违法。

## 引文与范围

发现问题必须给出已读段落中的逐字引文和真实零起始 paragraphIndex，不能编造或改写引文。
依据只能使用已经 readSources 读取、且该规则允许的 sourceId。
未发现问题、缺失条款要求解析完整且已经读取全文。目录没有标题不能证明正文没有约定。
没有读全时可以提交有原文支持的问题；不能确定的事项提交待核实，写清还缺什么。
缺失条款 quote=""、paragraphIndex=-1；无引文待核实同样用 -1 并填写 pending。

## 输出

每项用一句话说明核心问题和一句话给出修改方向，risk 目标不超过 80 字，suggestion 不超过 120 字，
impact 不超过 60 字；保留实质条件，不重复原文与依据，不默认起草完整替换条款。
没有调用方确认的拟约定输入时，不自行填入建议天数、费率、金额、法院或仲裁机构名称。
同类规则仍分别提交；同一风险只说明本规则关注的方面，不复制其他规则整段分析。
提交前对照原文核对条款编号与删除/保留动作；选择诉讼应删除仲裁约定，选择仲裁应删除诉讼约定。
互斥方案分别表达；检查不通过时修正建议或明确待核实，不把措辞一致当作法律适用已经确认。

每条规则通过 submitFindings 提交一条结论：ruleId、kind、risk、severity、quote、paragraphIndex、
basis、impact、suggestion、pending。kind 为发现问题/未发现问题/缺失条款/待核实。
依据不足时使用待核实，basis 可以为空。所有结论保留待人工复核状态。
跨段论证可补充 citations 数组，每项为 paragraphIndex、quote；主引文仍填写 quote 和 paragraphIndex。
提交失败时根据工具返回的错误修正后重新提交；不得用自然语言总结代替结构化提交。
读取、调用次数或时间达到上限时保留已有结果和未完成项，不伪造完整成功。
